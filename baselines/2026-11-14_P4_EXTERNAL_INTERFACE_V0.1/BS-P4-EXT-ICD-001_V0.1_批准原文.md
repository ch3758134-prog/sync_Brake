## 0. 本轮新增的工程价值与已批准依据

### 0.1 为什么需要这份接口合同

已批准的 `BS-P4-OPTIONS-001 V0.1` 已经比较了制动意图 `TRIG-A～D`、运动传感 `MOT-A～C`、系统组织 `PWR-A～C`，并提出 `SAFE-01～07` 与 `DEC-HW-01～07` 的证据要求。但**比较方案不等于拿到了能够设计、安装或验收的真实接口**。

本文补齐的不是第二轮方案比较，而是建立一条可检查的闭环：

`车辆/器件的真实来源和版本 → 接口要求 → 正常/故障工况 → 实物设计责任 → 可观测证据 → 负责人判定/签收`。

这些条目可直接用作未来原理图、线束图、实际制动器规格的**交接核对清单**，避免仅凭“接口存在”“通信成功”或“电压/电流大致相符”就推进真实制动功率设计。

## 1. 本轮建议固定的“接口记录”粒度（仅字段合同，不是数据结构）

**任一系统物理接口必须具备下列信息，才允许参与后续硬件和安全设计定型：**

| 接口记录字段 | 必填证据及检查事项 | 缺失时的判断 |
|---|---|---|
| `IF_ID` / 功能 / 所属产品 | 接口编号、车辆/主控/传感/制动/维护实际边界、适用 Variant 与 Board | 无法确认配置时 `OPEN` |
| `SOURCE_DOCUMENT` | 供应商手册/车辆接口/原理图/线束图的来源、版本、日期和受控位置；必要时校验值 | 文件名、聊天描述不能代替真实来源 |
| `CONNECTOR_AND_WIRING` | 物理连接器、配对件、针脚与功能、地/屏蔽/线束长度和安装条件 | 实际引脚和连接方式不写入冻结设计 |
| `ELECTRICAL_ENVELOPE` | 正常电压/电流、电源极性、瞬态、负载、温度、隔离与参考地；单位、工况及容差 | 不能开展电气定额/保护器件定型 |
| `SEMANTICS_AND_TIMING` | 电信号或信息何时代表“有效制动意图/物理运动/执行状态”；有效/无效、电源与断联时序 | 不能凭某个高低电平或报文内容断定真实意图 |
| `FAULT_MODES` | 开短路、反接、丢帧、接地断开、欠压、短接到电源、误插、复位和机械松脱等适用故障 | 未分析故障检测与整车后果则 `OPEN` |
| `OBSERVABILITY` | 哪些故障可检测；由哪一级硬件/系统发现；哪些无法检测或不能区分 | **“没有报警”不能推定“实际工作正确”** |
| `OWNER_AND_TEST` | 设计责任、独立测点、实验方法、通过判据、复核与签收方 | 缺判据则 `TEST_PLAN_ONLY` |
| `VERSION_LINK` | 与制动器型号、线束/板卡 Revision、软件 Variant/Release 的兼容性 | 不可把不同版本资料混用 |

### 1.1 接口证据状态（建议统一）

- `IDENTIFIED`：接口边界和资料提供者已知，但仍可能缺真实规格。
- `SUPPORTED_BY_SOURCE`：有准确版本的车辆/厂商/硬件原始依据，**不等于实测验证**。
- `DESIGN_REVIEWED`：已据原文完成电气/功能/故障设计评审，但尚可需要台架证据。
- `TESTED_FOR_SCOPE`：只针对标明的实物、工况和测试范围有证据；不得外推到全部车型。
- `APPROVED_FOR_USE`：负责人根据适用产品、约束、安全与可重复证据批准使用。
- `OPEN` / `BLOCKED`：缺事实或安全准入；不得只因已经写成表格就升级状态。

**本稿所有真实接口都仍为 `OPEN` 或 `BLOCKED`，并无接口已达到 `APPROVED_FOR_USE`。**

| 系统接口 | 真实源/目的 | 必须取得的物理/功能证据 | 关键风险与不可忽略的盲区 | 关联要求 | 状态 |
|---|---|---|---|---|---|
| `SYS-IF-01` 制动触发 | 牵引车辆/线束 → BrakeSync 输入 | 触发来源、引脚、电平/极性、有效语义、供电与共享地、噪声/故障状态、安装车型限制 | 误触发导致意外制动，失触发导致制动不足；运动信号不可代替该接口证明意图 | `TRIG-A～D`，`PCB-02`，`HA-01/02`，`SSR-02/03` | `OPEN` |

## 3. 必须区分的三条物理因果链

### 3.1 制动意图链（TRIG，制动需求的证据）

`驾驶员/牵引车实际制动行为 → 车端真实物理信号或可信协议 → 车辆/线束传输 → 输入电路测得的电气事实 → ECU 判断的意图证据`。

**不容省略的判定点**：信号来自哪个真实车型/接口？该信号是不是驾驶员制动意图而非其它车辆功能？何时有效？欠压/接地故障/误接时会表现成“有效制动”还是“有效松开”？如果两者不能区分，系统应报告什么状态？

**未来必须提供的原件**：目标车辆的真实接线定义（含接口图和变型适用限制）、车端与拖挂地/电源说明、故障工况下的变化规律。没有它们，不冻结 `TRIG-A` 或触发输入前端设计。

### 3.2 运动测量链（MOT，物理测量及其可信度）

`拖挂实际纵向运动 → 传感器安装位置和坐标 → 物理传感器采样 → 模块滤波/通信 → ECU 收到的数据 → 与实际运动对应的质量`。

必须区分：真实运动的方向/单位、传感芯片安装轴、模块是否进行了滤波与缩放、设备采样与收包时间差、传感器是否随轮端/车体的装配方式变化。若采用外置 CAN 模块，不能把总线可靠传输当成测量值可靠；若板载 MEMS，不能把 PCB 相对安装固定当成车辆纵轴姿态已可靠标定。

**未来必须提供的原件**：实际模块/芯片规格、协议、目标采样和安装条件、可支持的自检、校准和诊断方法、成本和装配工艺。`BMA510 PDF` 和“CAN加速度计”仍须分别确认真实型号及使用路径。

### 3.3 执行物理链（PWR/SAFE，最终制动的真实作用）

`可信的逻辑请求 → 系统执行资格/独立保护 → 功率驱动真实动作 → 线束和轮端线圈真实状态 → 电磁/机械制动效果 → 车辆响应`。

**五个不能合并的事实**：请求存在；物理许可成立；驱动级动作成立；测得某一电气量；轮端机械制动力真的达到目标。不同层的检测覆盖和故障盲区必须记录。对于失效器件短路、输出无法释放、单轮断路、左右不均、轮端机械老化，不得通过“正常 PWM/总电流”推断整体正常。

物理关断、限幅、维持、报警或维修处理，应在**真实车辆工况**、失效后果和硬件能力分析后决定；当前绝不填写“所有异常统一输出零”的控制动作。

## 4. 初步硬件失效链与观察覆盖矩阵（不能代替 FMEA）

| 失效场景 | 哪些现象**可能**可观测 | 主要观测盲区 | 应分配的实体责任 | 必须在下一阶段制定的测试/来源 |
|---|---|---|---|---|
| 车端制动输入开路/短路/误接 | 输入口电压、电源状态或冗余/诊断反馈（取决于实际电路） | 单线布置可能无法区分“有效松开”和“断线” | 车辆接口、输入前端、系统诊断 | 真实车端接口、输入故障注入和可检测性分析 |
| 运动模块通信正常但坐标/标定错误 | 报文格式可能完全正确，外部运动参考可能揭示差异 | 仅 CAN ACK/CRC 不证明物理量正确 | 机械安装、传感器、校准与系统验证 | 真实安装姿态、动态参考测量及偏差预算 |
| MCU 在复位、高阻或死循环 | 复位引脚/看门狗/电源状态、独立硬件监测信号 | 软件日志可能中断，功率级可能仍持续工作 | 供电/功率硬件及控制系统共同分配 | 断电/复位真值表、故障注入、实际门控/保护测点 |
| 功率 MOSFET/驱动级短路 | 可能出现异常输出电压/电流或温度 | MCU 命令为零并不能确保实际导通已解除 | 执行硬件、独立保护、系统安全 | 器件失效方式、能量限制与台架保护设计 |
| 轮端单支路开路/接触不良 | 有独立监测时可测电流变化 | 单总电流反馈可能无法区分所有分支 | 线束/连接器、通道拓扑与诊断 | 线束图、各支路负载、测量覆盖和误差分析 |
| 轮端卡滞或摩擦/机械能力退化 | 电流/电压可能正常 | 电气反馈无法直接证明机械制动力 | 轮端机械维护、车辆系统与真实台架 | 制动器制造商资料和轮端机械/热性能测试 |
| 供电瞬态/接地断开 | 供电监测和复位事件（取决于供电路径） | 掉电期间 MCU 可能无法记录，功率输出状态仍需硬件测定 | 电源/接地/保护、线束、整车安全 | 电源异常波形、默认态、热/故障保护分析 |
| 脱挂、驻车和应急系统相互干涉 | 取决于安装线路及独立器件反馈 | 控制器内部信号不能证明独立装置未受影响 | 车辆系统集成与安装/法规 | 车辆连接拓扑、设备说明及独立系统验收方案 |

**性质说明**：此矩阵仅是**初步观察覆盖问题清单**。真正的失效模式、单点故障、共因失效、诊断覆盖率、独立保护和残余风险必须由实物电路分析、正式安全流程及相应实验来证明；不引用虚构的定量故障率或 ASIL 等级。

### 5.1 原始资料的签收条件

1. **可追溯**：真实来源、型号、版本、适用变型与文件完整性可核验；适用时记录 SHA-256 和受控存储地址。聊天中说过“有资料”不算已签收文件。
2. **有授权**：第三方资料许可不明时不得未经许可公开上传。GitHub 只保存受控索引、校验值、访问责任和审查记录。
3. **可解释**：标明材料支持了哪个接口字段或哪条电气/机械要求；不支持的结论不得补全成“已确认”。
4. **可关闭**：由负责人明确审核“这个版本适用于哪一类车/制动器/PCB”。发现错版、原图不完整或无法确认时登记 `OPEN/RESTRICTED`。
5. **不越级**：原始规格到位 ≠ 原理图正确；原理图核对完成 ≠ 台架通过；台架通过 ≠ 道路或产品级验收。
