**项目**：BrakeSync 拖挂式房车电子同步制动控制系统

**状态**：`FOR_OWNER_APPROVAL`（本对话交付，未批准；不提交 GitHub）  
**依据**：已批准 P0–P8 V0.1 的产品目标、需求方向与工作计划；P2 系统需求框架及用户历史功能方案。

## 1. 本阶段要作出的决策

P0/P1 已批准，P2 的需求方向已批准，P3/P4 的总体设计方法与阶段计划也已批准。但“批准了计划”不等于具体系统功能已经分配完成。本文件推进 **P3 的第一项实质性系统设计**：产品边界、功能分配、信息流、安全责任和配置分离，不涉及实现代码或具体芯片。

**建议批准的系统级结论**（仍须负责人审阅）：

- **决策 S-01**：BrakeSync ECU/主控制器是自动同步制动的唯一实时决策主体，App 或 LCD 只用于参数配置、状态查看和诊断，不构成实时控制环路的必须在线节点。
- **决策 S-02**：控制信息从两个独立的逻辑输入概念开始：制动意图/触发信息和运动/减速度信息。物理来源、总线和传感器型号以后再确认，不把牵引车 CAN 作为先验必需条件。
- **决策 S-03**：用户配置的核心语义固定为「房车重量制动档」与「同一重量档内的制动力等级微调」，并具备当前生效值、确认保存及状态/故障反馈；**制动等级 1–10 可以作为优先选项，但控制映射、档位重量区间及默认值尚不冻结**。
- **决策 S-04**：将“生成逻辑制动请求”和“实际功率执行及安全许可”设为两个独立系统责任边界。当前云途 EVB 的真实功率输出始终禁止。
- **决策 S-05**：LCD 与手机 App 是不同产品 Variant 可采用的 HMI，不是两个独立制动控制算法；当前开展 App 研究不等于首发 SKU 已被批准，也不要求 App 运行时持续在线。
- **决策 S-06**：所有影响制动安全的异常处理须由后续系统危险分析和具体执行电路条件决定；不提前规定“任何故障一律断电”或“异常继续输出”等未经论证的行为。

## 2. 系统外部边界

```text
牵引车/驾驶员制动行为          房车运动/减速度状态
           |                           |
           v                           v
    [制动意图输入]               [运动信息输入]
            \                         /
             \                       /
              [ BrakeSync 主控制器 ]
             ┌───────────────────────────┐
             │ 输入可用性与状态判断      │
             │ 重量档与制动力参数        │
             │ 自动同步制动决策          │
             │ 故障诊断与安全许可管理    │
             └───────────────────────────┘
                    |              ^
                    v              |
             [逻辑制动请求]    [HMI 参数/查询]
                    |              |
             [执行/安全电路]   App/BLE 或 LCD
                    |
              [拖挂制动器]
```

**边界说明**：图中的功率执行电路、真实制动器属于完整产品目标，**不代表现阶段 EVB 已具备或者被允许接通它们**。产品侧目标制动器类型、轴数、车重、电流、供电电压及牵引车输入电气形式尚未冻结。

| SF-03 | 运动信息获取、坐标与可信度判断 | 主控制器的输入边界 | 加速度/减速度信息 | 有时间依据和质量状态的运动信息 | 传感器及通信待决 |
| SF-04 | 自动同步制动决策 | 主控制器 | 可信输入、配置、运行资格 | 逻辑制动请求与受限原因 | 控制律及定量参数待设计 |
| SF-05 | 制动请求执行与保护 | 执行硬件及其受控接口 | 有效制动请求、安全许可 | 受限、禁止、执行及反馈 | 实物电路未确定；EVB 禁止功率输出 |
| SF-06 | 用户参数管理及持久化 | 主控制器 | 重量档、等级、更改请求 | 校验、生效、保存、回读结果 | 档数/区间/参数表待决 |
| SF-07 | 运行状态、诊断和异常提示 | 主控制器产生，HMI 呈现 | 输入、配置、系统/执行异常 | 可区分的状态与故障原因 | 完整故障清单及策略待危险分析 |
| SF-08 | 用户交互与连接 | App 或 LCD Variant | 用户读取与设置请求 | 显示、命令受理结果和真实生效状态 | HMI 产品组合待决 |
| SF-09 | 维护、识别与版本管理 | 主控制器及维护界面 | 产品版本、配置/诊断请求 | 可追溯身份、配置/故障记录 | 工程需求保留，不定义 OTA 必须 |

**职责规则**：没有一个外部显示/连接节点可以单方面决定制动输出；没有一个通信模块可以绕过主控制器的参数合法性、安全许可和回读机制。

## 4. 首次使用与日常使用的产品闭环

### 场景 UC-01：首次安装与设置

1. 安装人员完成经产品说明核准的电气连接；设备上电先报告自身状态。
2. 用户选择适用的拖挂重量制动档（**实际档位及重量区间待决**）。
3. 系统应用该档经批准的默认制动力或提示进一步配置（**默认值待标定**）。
4. 用户调整制动力等级；系统返回受理/拒绝、当前生效值和保存结果。
5. 配置与状态满足已批准条件后才可能进入正常运行资格；实际制动效果必须在具备安全条件的后期台架和使用验证中确认。

### 场景 UC-02：日常同步制动

1. 用户不需要打开手机 App。
2. 主控制器持续判断制动相关输入、运动状态、有效配置和运行资格。
3. 主控制器形成受约束的逻辑制动请求；产品级安全执行路径后续单独设计与验证。
4. 异常时记录原因并向可用 HMI 呈现，但物理安全动作要按照危险分析结果实施。

### 场景 UC-03：调整与恢复

1. 用户修改制动力等级时，不改变重量档。
2. 未授权、不允许工况、超限或通信失败的请求不能显示为“已生效”。
3. 重新上电时仅恢复有效、适配当前版本且经校验的配置；无效配置有明确的未就绪/受限路径。

## 5. 输入、输出、状态合同（仅系统语义，不是软件结构体）

| 合同 | 必须表达的语义 | 目前禁止预填的事项 |
|---|---|---|
| SI-01 制动意图 | 是否有效、当前意图、最近更新时刻、来源与异常原因 | 引脚、极性、输入电压、硬件滤波阈值 |
| SI-02 运动信息 | 纵向定义、单位/符号、有效性、最近采样时刻、安装方向约定 | 具体 CAN 帧、I²C 地址、量程、刷新频率 |
| SI-03 配置 | 重量档、制动力等级、当前生效值、参数版本及保存结果 | 具体档位范围、电流/PWM 标定表、NVM 地址 |
| SI-04 系统状态 | 初始化、未就绪、可运行、逻辑制动请求、故障及限制原因 | 未经危害分析的物理输出动作 |
| SI-05 逻辑制动请求 | 请求的有效性、边界约束、禁用原因与时间依据 | PWM 频率、执行电流、驱动电路与实际启用许可 |
| SI-06 HMI 交互 | 设置请求、是否受理、何时生效、保存/回读、故障显示 | BLE UUID、AT 指令、APP API 或 LCD 屏幕规格 |

## 6. 关键异常情景与应产出的系统需求

| 情景 | 必须定义的能力 | 当前安全边界 |
|---|---|---|
| 上电/复位 | 未完成自身检查前不可报告正常制动就绪 | EVB 永远不允许实际功率输出 |
| 制动意图缺失或异常 | 识别缺失/超时/电气不合理；报告状态 | 实际动作须与输入硬件及危险分析一致 |
| 加速度样本失效/断线 | 识别丢帧、过期、异常值和安装方向问题 | 不能把失效样本当作正常减速度 |
| 配置损坏或掉电写中断 | 校验、回退与明确未就绪路径 | 不允许未确认配置变成执行值 |
| 手机断链/蓝牙异常 | 通信状态与主控制相互隔离 | 断链不直接构成制动请求或解除安全限制 |
| 执行器/功率异常 | 未来应具备反馈、诊断和独立保护方案 | 执行硬件尚不存在，不能宣称保护已有效 |
| 低压/看门狗/MCU 故障 | 后续应定义硬件默认态、故障检测与恢复条件 | 不预断所有行车工况的唯一安全动作 |

## 7. Variant 与当前验证平台的区别

| 类别 | 目的 | 当前应如何处理 |
|---|---|---|
| 研发验证配置 `EVB-LAB` | 云途开发板上验证输入、通信、运动和软件独立能力 | 是**实验平台**，不是可上车产品 Variant；真实功率输出禁止 |
| 普通 HMI 产品 Variant | LCD + 本地操作 | 功能语义纳入系统设计；实体屏幕及操作器件待后续配置决定 |
| 智能 HMI 产品 Variant | BLE + App 配置/查看/诊断 | 功能语义纳入系统设计；首发与平台范围仍待确认 |
| 共用控制平台 | 维持制动请求、配置和故障行为一致 | 以系统合同为权威，不能为某个 HMI 重写一套业务规则 |

## 9. 系统运行状态与事件矩阵（P3-SYS-02 初稿）

这一节定义**系统业务状态**，不是 MCU 内的任务状态，也不是经验证的制动安全状态机。当前 EVB 任何状态都不允许对应真实功率输出。

| 业务状态 | 进入事件或必要前提 | 应向外呈现的信息 | 允许的系统行为 | 未决条件 |
|---|---|---|---|---|
| ST-INIT 初始化中 | 上电、复位，开始诊断 | 初始化中/尚未就绪 | 读取自身配置、检查必要接口 | 上电诊断覆盖、时限 |
| ST-UNCONFIGURED 未完成有效配置 | 无可用参数、参数失效、首次配置未完成 | 请完成配置/无有效配置 | 允许受控查询、配置与诊断 | 缺省参数是否可用于应急策略，须危险分析 |
| ST-STANDBY 待命 | 必要输入和配置有效，且无阻塞运行的故障 | 系统待命，不代表功率安全认证 | 监测输入、计算制动需求条件 | 真实产品的安全准入条件 |
| ST-BRAKING 逻辑制动中 | 有符合条件的制动意图、运动输入与系统资格 | 逻辑制动请求活动 | 根据受控参数更新逻辑请求 | 输出如何映射、超时如何处理 |
| ST-LIMITED 受限/降级 | 存在已识别但处理策略尚未定版的条件 | 受限及其原因 | 只能执行被危险分析允许的动作 | 不预设受限时继续输出或立即停用 |
| ST-FAULT 故障 | 必要条件丧失、关键诊断失败等 | 可追溯故障代码/事件 | 诊断、受控恢复与维护操作 | 故障锁存、复位和电气保护策略 |
| ST-SERVICE 维护 | 经授权进入维修/诊断用途 | 维护模式 | 查询信息、执行受限的安全诊断 | 运行时是否允许进入、认证机制 |

事件与转换规则候选：

| 事件 | 原状态 | 目标状态/动作 | 不可省略的验证依据 |
|---|---|---|---|
| 上电/复位 | 任意 | ST-INIT | 上电默认态与状态报告 |
| 配置无效 | ST-INIT 或 ST-STANDBY | ST-UNCONFIGURED 或受控故障状态，按危险分析 | 参数损坏与版本不符试验 |
| 完成有效配置 | ST-UNCONFIGURED | 经必要自检后方可 ST-STANDBY | 保存/重启/回读验证 |
| 有效制动意图到达 | ST-STANDBY | 有条件地转 ST-BRAKING（逻辑） | 制动输入与运动信息时序和质量 |
| 制动意图解除 | ST-BRAKING | 按已验证控制策略返回 ST-STANDBY | 释放控制策略、实时性验证 |
| 运动样本失效、供电异常、接口异常 | ST-STANDBY 或 ST-BRAKING | ST-LIMITED 或 ST-FAULT；**物理处理待安全分析** | 危险分析与故障注入 |
| App 断连 | ST-STANDBY 或 ST-BRAKING | 不因为手机离线直接改变主控运行资格 | 断连/重连测试 |
| 维修请求 | 允许的安全工况 | ST-SERVICE | 用户授权、互锁与拒绝路径 |

**状态机门槛**：进入实现阶段前必须明确上述候选状态中哪些可以合并、哪些需要更细分，尤其是 ST-LIMITED/ST-FAULT 的**具体车辆工况下后果**。不能把业务状态名当作安全批准。

| 接口 ID | 外部对象 | 交换的信息或能量 | 核心不确定项 | 主要危险/质量问题 |
|---|---|---|---|---|
| IF-01 | 牵引车制动相关信号 | 驾驶员制动意图/有效触发 | 物理来源、隔离、电压、极性、故障检测 | 误触发、漏触发、输入短路 |
| IF-02 | 运动传感器或其模块 | 加速度/减速度/状态 | 实际传感器、安装、方向、接口、速率 | 方向颠倒、零漂、数据超时、干扰 |

| IF-04 | 电磁制动执行电路和房车制动器 | 执行指令、供电功率、执行反馈 | 电路拓扑、轴数、电流、线束及保护、制动器适用性 | 非预期制动、制动不足、失控输出、断线 |
| IF-05 | LCD/实体操作 | 参数、状态、用户操作 | 是否配置该 Variant、安装位置与交互条件 | 错误输入、误导显示、行驶分心 |
| IF-06 | BLE 模块和手机 App | 查询、配置请求、故障状态及回执 | 蓝牙模块、认证、协议、断线、重放 | 未授权调参、假成功、状态陈旧 |
| IF-07 | 维护/生产检测接口 | 版本、参数、故障与检验状态 | 物理通道与权限、追溯要求 | 未经授权绕过禁能、标定丢失 |

### 早期危险源分析准备（**不是正式 HARA**）

| 危险主题 | 可能后果 | 在 P3/P4 应补的证据 | 当前约束 |
|---|---|---|---|
| HZ-01 非预期拖挂制动 | 行驶稳定性降低、车辆受力异常 | 故障工况、执行回路、默认上电态和功率保护需求 | EVB 不得驱动实际制动器 |
| HZ-02 需要制动时输出不足 | 刹车距离、牵引车/拖挂负担增加 | 适用质量、速度、制动器配置、输出能力 | 不宣称系统已满足制动性能 |
| HZ-03 制动中异常中断或保持 | 冲击、牵引力变化或持续拖拽 | 按工况的失效安全策略、独立关断或限制路径 | 不一概断言“立即断电就是安全” |
| HZ-04 参数或重量档错误 | 制动偏强或偏弱 | 档位范围、确认、保存与合法性校验需求 | 不凭空填写重量/电流映射 |
| HZ-05 传感输入失真 | 错误制动决策 | 传感器安装、校验、时限与冗余策略 | 不使用未确认坐标和单位 |
| HZ-06 电源/复位异常 | 输出失控、错误恢复或设备损坏 | 电源电路、防护、复位/看门狗失效案例 | 需要最终 PCB 和台架证据 |
| HZ-07 无线配置受攻击或误操作 | 运行参数被恶意/意外更改 | 身份、权限、序列号、回执及工况互锁 | 未确认协议前不连真实执行控制 |

**这张清单是危险分析输入，不是风险等级结论**。真实车辆安全需求必须在目标车型、质量范围、制动器和输出电路确定后形成独立可追溯的安全分析。
