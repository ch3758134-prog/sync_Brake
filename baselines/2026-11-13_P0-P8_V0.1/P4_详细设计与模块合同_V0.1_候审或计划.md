## 0. 阶段目标

P4 是把已批准的系统需求和架构，变为**执行者无需猜测重要行为即可编译、测试和复核的详细合同**。目前 P2/P3 尚未批准，所以本文件是详细设计的**基准框架与可审候选**，不是已冻结的实现说明。禁止把未确认 SDK、芯片、蓝牙命令或 CAN 报文写成实际目标接口。

### P4 最终必须交付的完整规格集

1. C 模块职责、公开接口、数据结构、初始化/运行/关闭/异常/恢复、依赖关系；
2. 执行周期、时间基准、CPU/RAM/Flash 预算与性能测量计划（数值以目标板证据补齐）；
3. CAN/UART/I²C、传感器、BLE App 通信、参数存储和执行接口的 ICD；
4. 配置、运行状态、故障检测和恢复状态机；
5. 安全机制、功率输出禁止边界和可追溯验证用例；
6. 代码修改边界、测试桩和失败回滚方法，适于 ChatGPT 设计+Codex 按批准任务执行。

## 2. 系统状态设计合同候选

| 状态 | 进入条件（待安全审查） | 对外状态 | 允许的业务操作 | 故障及恢复 |
|---|---|---|---|---|
| `INIT` | 上电/重置 | 初始化中 | 只读诊断和受控初始化 | 任一必要服务失败须转未就绪或故障 |
| `INHIBITED` | 控制准入不满足或当前 EVB 强制限制 | 禁止真实执行 | 配置查询、隔离外设测试 | 不可凭 UI 解除禁能 |
| `READY` | 有效输入/参数及所需安全证明 | 可运行（仅逻辑） | 计算逻辑请求、配置准入检查 | 任何依赖失效进入明确受限路径 |
| `ACTIVE` | 满足制动决策条件 | 逻辑请求活动 | 生成/更新逻辑请求 | 失效响应由危害分析和执行硬件确定 |
| `DEGRADED` / `FAULT` | 检测到定义的异常 | 分级故障 | 只允许受审动作 | 恢复条件、锁存策略依故障定义 |
| `SERVICE` | 有权限的维护工况 | 维护态 | 受控只读/诊断 | **维护不得绕过制动输出禁止** |

在正式设计冻结前必须制作状态/事件二维矩阵，逐项标注：动作前提、转换目标、诊断代码、配置行为、输出边界及验证用例。**不得只画流程图，不处理复位/掉电/超时/故障注入。**

## 4. 关键服务与接口契约候选

| 逻辑接口（示意名，待批准） | 请求/返回语义 | 失败/并发约束 | 责任层 |
|---|---|---|---|
| `Board_Init` | 仅初始化符合已核对版本的时钟/复用/外设 | 失败返回并保留禁止执行状态；不得半初始化后报成功 | BoardCfg/BSW |
| `Time_GetMonotonic` | 读取可验证单调时基 | 时钟故障/时间不可信时明确报告 | BSW Services |
| `BrakeInput_Update` | 提交带来源和采集时刻的输入 | 拒绝异常格式和过期数据；不将无效覆盖为有效 | ASW |
| `Motion_Update` | 提交有轴方向/单位的运动样本 | 未校准与异常样本触发对应状态 | ASW |
| `Params_Validate` | 校验重量档和等级等配置 | 禁止无意更改其他参数、检查 schema | ASW |
| `Params_Commit` | 返回“已受理/已写入/已生效”的明确定义 | 写中断/断电/重复请求不假成功 | ASW+NVM |
| `BrakeControl_Evaluate` | 依据可信输入/配置形成逻辑请求 | 输入异常、限幅、禁能有原因代码 | ASW |
| `Diagnostics_GetStatus` | 读取实际设备当前故障/原因 | App 缓存不得冒充设备已恢复 | ASW |
| `Transport_Exchange` | 严格版本化读写与错误映射 | 未知模块/UUID/权限/超时返回可区分错误 | BSW/BLE |

不要求立即采用上述函数名；已有 API 以**准确的实际源码**为准。正式 P4 要针对每个公开函数补齐：调用方、参数范围、线程/ISR 许可、所有权/生命周期、返回码、耗时、重入限制和单元测试用例。

## 5. 蓝牙 App 共同接口定义（ICD 候选骨架）

后续形成一份权威 `BLE-ICD`，不允许固件与 App 分别猜测。至少包含：

- 传输事实：外接模块确切型号/固件、UART 电平和参数、是否 AT/透明传输、BLE 服务及特征 UUID 的原厂或现场证据；
- 设备身份：产品设备 ID、配对方式、许可角色、鉴权、会话超时、重放保护；
- 请求与回执：协议版本、消息类型、事务/请求 ID、长度、数据类型、校验、错误码、设备端执行状态；
- 设置与回读：`weightPreset` 和 `brakeLevel` 的单位、有效范围、提交/生效/持久化时机，断连前后的一致性；
- 状态和故障：设备运行/连接/受限/故障的代码表、时间戳与缓存标志；
- 兼容与回滚：App 与固件的协议版本组合、未知字段策略、不可恢复错误提示；
- 测试：伪设备、越界命令、重放、断连、重连、超时、写失败、掉电重启、升级前后兼容。

**严禁使用当前 Flutter Mock 的三档示例当最终重量档数量，严禁将历史 WLT8016 规格引用当作已经得知 GATT UUID。** 真正危险的执行动作不得通过普通 App 配置写入路径绕开安全准入。

## 6. CAN 与加速度设备适配详细合同

1. 首先确认手中模块究竟是 CAN 加速度模块还是直接 I²C/SPI BMA510 板；若是前者，需要整套**模块级**报文协议、供电和 CAN PHY/终端说明；若是后者，需要模块板级电平/引脚和原厂芯片配置与实测。
2. 目标 CAN 接收必须区分总线中断处理与业务消息处理；过滤、FIFO/队列、丢包、Bus-off 恢复的策略不可由 `main()` 临时堆砌。具体中断/DMA 实现由精确 YTMicro SDK 决定。
3. I²C 开发板 EEPROM PTD0/PTD1 的 RevA vs RevC `I²C0/I²C1` 差异属于工程阻塞项；不能把手册旧编号当可靠复用；按实际芯片 SDK 与原理图先核对。
4. 预留设备健康、采样新鲜度、单位、零偏、温度/自检及故障码；正常数据与坏数据用一致上层合同表示。

## 7. 参数、诊断和安全设计

- **参数**：独立决定用户档位/等级与受保护的工程标定区；有效值与正在编辑值分开；掉电原子性、默认和版本迁移需测试；保存操作的生命周期可追踪。
- **诊断**：故障事件表至少列检测原因、检测条件、错误计数/去抖、严重度、锁存/恢复、对 HMI 的可见语义及对应测试。不得用“返回 false”代替全部故障理由。
- **安全**：先形成危险清单、运行工况和允许动作矩阵，确认软件/硬件安全分配；目前 `BrakeSystem_CanEnableBrakeOutput() == false` 只能作为读取到的旧源码事实，不是硬件证明。
- **执行器**：后续真实电磁制动执行需电气/热/过流/短路/断线、复位和故障安全实现数据，不能因为 P4 有章节便开始焊接功率输出。
