## 2. 为什么没有 P9

当前 BrakeSync 在原 `P0 → P1 → P2 → P3` 的编号约定上，按照 `ProjectControl 4.6.1 / portable/process_catalog.json v1.2.0` 的主要工程过程，映射为 P0–P8。目录中另外存在 `research-investigation`（专题研究）和 `continuous-governance`（全周期治理），但它们是**跨阶段活动而不是在某个时间点才启动的顺序阶段**。后续产品维护/持续迭代由 P8 的交接机制及 G 治理承接，**不凭空增加必须逐级审批的新 P9**。

| 内部阶段 | ProjectControl 责任过程 |
|---|---|
| P0 | initiation |
| P1 | current-state |
| P2 | needs |
| P3 | architecture |
| P4 | detailed-design |
| P5 | implementation |
| P6 | integration |
| P7 | verification |
| P8 | release-handover |
| R（横向） | research-investigation |
| G（横向） | continuous-governance |

这些 P 编号不是 Automotive SPICE、ISO 26262 等外部标准规定的强制编号。

建议一次看完所有文件，先针对以下三层做决定，而不是要求你未来再逐份点“继续”：

1. **项目方向与产品边界**：P0/P1 有效，无须重审已确认事实；审阅 P2 的基础需求、增强功能边界与 `OD-01..09`。

3. **执行与验收计划**：审阅 P5–P8 中每个后续交付的最低证据条件、协作权限与试验边界；**不能提前宣布实际任务、测试或发布成功**。
