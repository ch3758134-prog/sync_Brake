## 1. 开发边界和四条工作流

| 工作流 | 可立即按独立授权研究/准备 | 实际修改/实测启动前必须补齐 | 完成证据 |
|---|---|---|---|

## 2. 可分配的实施包（本次为 TASK-CANDIDATE，不是 Codex 命令）

| 工作包 | 建议输入版本和文件范围 | 实施内容 | 必测与完成判据 | 明确禁止 |
|---|---|---|---|---|
| `FW-01` 依赖与入口核对 | `firmware/` 当前 HEAD、官方 SDK 文件目录 | 梳理 `main`、BSW 接口、BoardCfg、目标时钟/中断启动 | 文件与调用关系图、无隐含 SDK API | 不趁机重构整个仓库 |

| `FW-03` CAN 数据通路 | CAN Driver 与独立 CDD 输入接口 | 确认模块 CAN 物理层和报文合同，区分接收/过滤/错误恢复与 ASW | 不合法 DLC/ID、超时、Bus-off/重启；真实 CAN 实测 | 不猜测 CAN ID、波特率、消息格式 |
| `FW-04` 加速度输入 | CDD + ASW Motion 合同 | 按实际模块 I²C/SPI/CAN 接入，时间戳/坐标/质量统一 | 芯片/模块身份、数据变化、断线/错数据 | 不把 BMA510 芯片等同 CAN 模块 |
| `FW-05` 蓝牙模块 | UART 基础 + BLE 设备/协议层 | 模块复位/命令或透传、真实设备身份、故障状态与缓冲管理 | 按原厂和现场证据测试收发、超时/断连 | 不猜测 AT/GATT UUID |
| `FW-06` 制动逻辑 | ASW State/Control/Diagnostics/Parameters | 按批准需求设计纯逻辑请求与受限状态 | Host 确定性、坏数据、参数异常、无功率输出 | 不接功率驱动、不激活 MCU 实制动引脚 |
| `APP-01` App 真实传输 | `app/lib/transport/` 与共用 ICD | 实现与 Mock 严格分离的已批准 BLE 连接和读写 | 模拟异常 + Android/iOS 按批准目标实机测试 | 不单方面定义协议，不冒充 Mock 为真设备 |
| `APP-02` 业务状态/配置 | `app/lib/domain/`, UI, tests | 规范连接/故障、制动档、等级、提交/回读 | 边界、拒绝、断链、回读与缓存标志 | 不把模拟三档定为正式产品档位 |

上表为**候选任务组合**。每个工作包须在执行前单独给出“文件清单、允许改动、禁止事项、上游版本、测试方式和验收人”；不能将整个 P5 文档当成允许 Codex 自主修改全部文件的授权。

## 4. 启动/运行与代码设计约束

- MCU 入口保持简洁：启动时钟、Board、OS/轮询/服务、ASW 后进入稳定调度。实际驱动逻辑不应长期塞入 `main()`。
- 中断/DMA 路径按真实云途 SDK 实现；ISR 的最小职责、数据缓冲和上下文并发安全要有审查和测试。
- 服务接口应返回具体错误状态，禁止未绑定 Driver 静默成功。
- 公开 C API 应表达英文稳定语义，配简洁中文注释；注释重点说明依据、硬件约束、错误边界；复杂框架、重复 HAL、隐式全局状态要受约束。
- 当需要处理超时、循环缓冲、错误恢复时，明确容量和溢出行为，不能只验证理想单字节正常路径。
- 参数、协议、控制策略共享数据类型不允许因模块方便而隐式修改上游需求。

## 5. 测试顺序及“通过”定义

| 级别 | 能说明什么 | 不能说明什么 | 基准例子 |
|---|---|---|---|
| 源码/静态审查 | API/逻辑与风格可被检查 | 能实际运行 | Driver 头文件审查 |
| Host Build PASS | 当前 Host 编译命令成功 | Target SDK/链接通过 | CMake + `-Wall -Wextra -Werror` |
| Host Unit PASS | 指定输入与桩的逻辑测试成功 | 真实器件接口通 | `ctest` 原始报告 |
| Target Build PASS | 对精确 MCU/SDK/工具链编译链接成功 | 烧录和实物运行 | Linker、启动文件等完整构建日志 |
| 烧录成功 | 程序进入指定器件 Flash/ROM | 功能正确 | 烧录器、芯片 ID、校验日志 |
| 实板运行 | 对指定供电与目标硬件观察到运行 | 模块稳定和安全性 | UART/LED/寄存器/探针记录 |
| 模块实测通过 | 真实模块在定义工况符合具体合同 | 产品系统验收 | CAN/IMU/BLE 全链路记录 |
| 产品级验证 | 指定产品硬件/工况满足批准要求 | 未测试的其他工况 | 未来台架/实车/安全证据链 |

可重复构建需要 SDK 和工具链版本、命令、源码 commit、配置、目标 MCU/板卡 Revision 一并存档。历史编译截图不能在 SDK 已变更后冒充当前 Release 证据。
