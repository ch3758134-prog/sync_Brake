## 0. 验证必须证明什么

P7 不是测试清单越长越好，而是明确**哪个产品/版本/环境已满足哪条批准需求，并用什么原始证据证明**。本文件为验证策略与待执行矩阵，不是产品级验证报告。未确定目标整机 PCB、电磁制动器规格、危险工况、市场法规、量化性能指标之前，不能定义虚假的“量产 PASS”。

## 1. 验证的四类对象和两条完全不同的主线

| 对象 | 环境 | 可证明的边界 | 不可证明 |
|---|---|---|---|
| 逻辑模块 | Host 单元测试与模拟输入 | 数据类型、逻辑分支、拒绝和确定性 | MCU 寄存器、外部模块响应、真实硬件安全 |
| 目标外设 | 已确认云途 EVB + 官方 SDK + 外接模块 | 对应特定接线/条件下的真实通信、时序和故障 | 最终产品功率驱动或整车制动性能 |
| 联机 HMI | 已确认 App 手机 + 真 BLE 模块 + EVB | 设备发现、鉴权、状态、受控设置及回执 | 手机实时控制安全闭环、实际制动力 |
| 整机产品 | 将来的正式 PCB、制动器、供电和受控试验场景 | 才能覆盖热、电流、物理制动和动态工况 | 未覆盖车型/法规/误用场景 |

**主线 A：EVB 软件/外设验证** 可在现阶段筹备实施；**主线 B：真实功率/台架/车辆安全验证** 暂不具备条件，不得靠 A 的成功把 B 标记为完成。

## 2. 需求追溯—验证矩阵（计划编号，非已有测试通过记录）

| 验证 ID | 关联需求 | 主要刺激/情境 | 接受判据必须观察到什么 | 环境和当前状态 |
|---|---|---|---|---|
| `VT-INIT-01` | `SYS-INIT-001…003` | 上电、初始化失败、未绑定服务 | 未就绪/故障状态可识别，不报告可正常制动 | Host/EVB `NOT_RUN` |
| `VT-IN-01` | `SYS-IN-001…007` | 信号丢失、样本过期、传感异常/方向翻转 | 无效样本不进入正常控制，恢复有条件 | Host/模块实物 `NOT_RUN` |
| `VT-CTRL-01` | `SYS-CTRL-001…005` | 断开 App、改变合法配置/输入 | 逻辑控制行为确定，主机不依赖手机在线 | Host/EVB `NOT_RUN` |
| `VT-CFG-01` | `SYS-CFG-001…008` | 有效/非法参数、写入中断、旧版本 | 档位和等级互不影响，生效与保存结果一致 | Host/目标 NVM `NOT_RUN` |
| `VT-HMI-01` | `SYS-HMI-001…006` | LCD/App 显示、非法操作、断连 | 设备状态一致、清楚区分真实/模拟与失败 | App/EVB `NOT_RUN` |
| `VT-BLE-01` | `SYS-COM-001…004`, `SYS-SEC-*` | 配对、伪设备、重复/乱序/丢包、重连 | 未授权设置不生效，已受理/已提交/已生效准确 | 手机+真 BLE `NOT_RUN` |
| `VT-DIAG-01` | `SYS-DIAG-001…004` | 故障注入、抖动、锁存和恢复 | 预定故障级别、恢复条件和对外报告可查 | Host/EVB `NOT_RUN` |
| `VT-SAFE-EVB-01` | `SYS-SAFE-001…005`, `SYS-OUT-003` | 复位/异常/外设测试 | EVB 没有可触发的实际制动功率执行路径 | 源码/实物接线检查 `NOT_RUN` |
| `VT-PLAT-01` | `SYS-PLAT-001…004`, `SYS-LAB-*` | 未绑定驱动、不同 Board 目标、SDK/引脚冲突 | 报错与版本清楚，不把虚构外设当成功能 | Host/Target `NOT_RUN` |
| `VT-QUAL-01` | `SYS-QUAL-001…004` | 需求/产品配置抽查、构建重现 | 源码/测试/版本映射完整，指标有来源 | 文档/CI/工具链 `NOT_RUN` |
| `VT-PROD-OUT` | `SYS-OUT-001/002`, `SYS-SAFE-*` | 真正执行器、电气/热/故障/道路工况 | 仅在未来 HARA/设计/试验批准后确定 | **BLOCKED：无正式 PCB/安全准入** |

不得因已有 `firmware-host` 或 `app-static` 绿灯就把上述新编号的目标测试写为 PASS；这些用例尚未按这份矩阵在指定目标环境执行。

## 3. 测试设计应包含的精确信息

每条用例至少写明：**需求 ID、测试版本、进入状态、设备配置、输入/操作步骤、预期可观测结果、采样与计量方法、故障注入方法、完成准则、数据文件、缺陷/复验链接**。如果某个阈值（超时、最大延迟、PWM/电流、控制精度）还没有确定来源，填写 `TBD` 并列为阻塞，不靠工程师随手选择一个“看起来合理”的数字。

## 4. 失效与安全验证重点

### 4.1 当前 EVB 阶段

- 端口未绑定或模块缺失时，系统不能将空数据判成“传感器有效”；
- 输入源丢失、停更、校验失败或时钟异常时不产生未经批准的逻辑有效请求；
- 状态机上电/复位/错误/恢复路径可被独立测试，而不是只覆盖正常主循环；
- 蓝牙断连不会中断主控的独立控制职责，也不允许手机因断连/重放错误设置；
- 参数断电/写失败后的预期生效值和故障状态明确；
- 固件/接线/调试指令不具备实际制动功率使能能力；这条需要软件与硬件独立审查。

### 4.2 未来真实产品阶段（本次禁止宣称已覆盖）

真实产品必须在确定电磁制动器类型/数量、载荷、车速、附着、温度、供电、执行器驱动拓扑之后，识别危险和相应故障响应。故障可能需要受控降级而非简单关断；必须基于具体工况、法规定义和风险分析决定。应覆盖上电瞬态、掉电/欠压、MCU 死机、看门狗、驱动短路/开路/粘连、器件热失控、传感器异常、用户误设置、线路接触不良等，保留可重复的试验结果。

ISO 26262、Automotive SPICE、MISRA C 仅作为当前适用性研究与过程借鉴，不可宣称认证通过或任何 ASIL 等级。是否适用特定产品须按目标区域和用途调查。

## 5. 验证覆盖与度量规则

- **需求覆盖** = 有确定验证计划的批准需求 / 适用的已批准需求（计划覆盖）；
- **已执行覆盖** = 至少完成一次适用测试的需求 / 适用的已批准需求；
- **通过覆盖** = 证据显示全部必须判据通过的适用需求 / 适用的已批准需求。

以上是建议度量定义，不能通过分母剔除难测需求来虚增覆盖率。若一个需求需要 Host 与目标板联合证明，两种环境证据缺一不可；不可简单加总重复。

结果用 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`，`NOT_APPLICABLE` 必须说明产品 Variant、理由和批准依据。发现缺陷需要保留失败原始日志和复验版本，不能用新绿灯覆盖历史失败。

## 7. 验证评审与 P7 退出

1. 对指定有效需求版本建立双向追踪，测试结果必须指向精确产品配置和源版本；
2. 正常、边界、故障与恢复场景均有执行证据，无法执行的项明确阻塞和补证条件；
3. 目标环境真实满足所批准的验收标准，无不可接受未关闭危险或无依据风险接受；
4. 对尚未实现的物理制动输出测试，不得把 EVB 验证代替台架/实车测试；
5. 必须经负责人对**具体产品版本、目标场景及残余风险**做独立验收，不能用“继续”替代。
