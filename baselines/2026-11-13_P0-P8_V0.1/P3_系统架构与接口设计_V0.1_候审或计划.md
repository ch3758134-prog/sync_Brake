## 0. 阶段目的与产出边界

P3 要回答：**系统各部分由谁负责，怎样交换什么信息，故障怎样被隔离，为什么采用此方案？** 本文形成可审查的系统级架构和合同候选，不宣称已有对应 Target 实现。关键输入来自 `BS-P2-SYSREQ V0.1`，目前该输入仍为**候审需求**；所有相应架构决定只是受制于 P2 的候选，不能被下游当作冻结合同。

- 正式产出应包括：系统上下文和逻辑边界、功能/安全责任分配、方案比较与取舍、跨模块数据/状态/故障合同、Variant/Board/Release 配置边界、风险和验证依据。
- 不是本阶段产出：具体 GPIO 映射、BLE UUID、CAN ID/周期、控制公式标定数值、真实功率硬件参数、可执行固件、实测证明。它们须在来源齐备和对应设计批准后处理。

## 2. 系统上下文及接口边界

```text
牵引车/驾驶员操作、外部传感器、用户配置
        │          │            │
        └───────[ 受控的输入/通信边界 ]─────────────┐
                                                   ▼
                                      ┌─────────────────────┐
                                      │ BrakeSync 核心控制器 │
                                      │ 输入质量 / 状态 /    │
                                      │ 参数 / 控制 / 诊断   │
                                      └─────────────────────┘
                                          │            │
                                  [输出请求合同]   [状态/配置合同]
                                          │            ├── LCD（若配置）
                                          │            └── BLE ↔ App（若配置）
                                          ▼
                                [执行器与安全硬件边界]
                                —— 当前 EVB 仅模拟/隔离 ——
```

- **主控制器**负责制动相关决策、状态、信号质量、配置有效性与故障处理；不得以 App 在线为先决条件。
- **App/LCD** 负责呈现、提交受许可的设置请求、读取结果；不得直接写功率 PWM 或绕开主控状态判断。
- **执行器边界** 把业务制动请求与电流调节、PWM、驱动器、物理制动器分离；实际执行硬件属于未来独立安全论证事项。某些故障的正确安全反应取决于危险分析，不应武断写“所有情况下直接切断即安全”。
- **外部接口** 不假定牵引车 CAN 必需；如果加速度模块以 CAN 输出，仅说明传感器通信，不能据此更改产品的牵引车 CAN 依赖。

## 3. 核心分层与唯一职责（候选）

| 层/模块 | 应承担的单一职责 | 明确不承担 | 对外合同 |
|---|---|---|---|
| ASW / BrakeInput | 制动输入有效性、触发质量、更新时间、冲突状态 | CAN 寄存器、GPIO 中断 | `BrakeInputSample` 数据语义与质量标志 |
| ASW / Motion | 减速度/纵向运动语义、标定方向、样本状态 | 决定 BMA510 / CAN 物理驱动 | `MotionSample` 及新鲜度、坐标系 |
| ASW / BrakeControl | 在有效状态/配置约束下产生*逻辑*制动请求 | 功率驱动与未批准控制律 | `BrakeRequest`、限幅/禁能原因 |
| ASW / SystemState | 生命周期、准入/限制/故障状态转换 | 代替硬件失效安全措施 | `SystemStatus`、状态转换事件 |
| ASW / Diagnostics | 故障判据、锁存/恢复判定与事件 | 将 UI 显示当作真实故障消除 | 故障代码/严重度/动作要求 |
| ASW / Parameters | 参数语义、合法性、持久化事务请求 | 直接暴露底层 Flash 地址 | 参数 schema / 生效版本 / 提交结果 |
| ASW / HmiService | 参数与状态业务命令语义 | 手机平台/屏幕库依赖 | 同源 HMI 命令/事件 |
| BSW / Services | 时基、任务调度、非易失性写入、通信收发服务 | 制动力算法 | 服务接口与超时/错误合同 |
| BSW / Drivers & CDD | MCU 外设及特定器件接入，依真实 SDK 运行 | 制动业务策略 | I/O 访问、设备健康、Bus 数据 |
| BoardCfg | Board 实物版号、PinMux、电源电平、时钟及资源分配 | 自动改变产品功能配置 | Board 绑定描述与资源校验 |
| App / Domain & Transport | 设备/会话状态、业务请求、真实连接适配 | 直接作为制动实时环路 | BLE-ICD 版本化命令与回执 |

原则：某一能力只拥有一个权威实现；不得重复叠加 MCAL→Driver→HAL→Adapter 产生无用转发层。以现有 `BsPort` 作为起点审查依赖和性能，**不要因为本表存在就重构正在运行的代码**。

## 4. 关键方案比较及推荐条件

| 议题 | 候选 A | 候选 B | 当前工程判断（尚未批准） | 必须补证 |
|---|---|---|---|---|
| 运动信息 | 直接 I²C/SPI 加速度芯片 | 外部 CAN 加速度模块 | ASW 使用统一运动样本合同，底层可替换；当前实物未识别前不二选一 | 外购模块型号、针脚/协议/刷新率、供电电平 |
| 制动触发 | 独立制动信号输入 | 受信任的通信输入 | 保留输入语义抽象；两者故障模式与许可不能偷换 | 实际信号源、电气保护与安全状态 |
| HMI 形式 | LCD 直接操作 | App BLE 配置 | 共用参数/状态语义；产品 SKU 由 Variant 决定 | OD-01，首款产品形态 |
| 固件执行 | 分层单循环定时任务 | 引入 RTOS | 优先可测、确定、低资源开销；是否需要 RTOS 必须测得调度/资源理由 | MCU 性能、运行时限、外设并发需要 |
| 固件互连 | 同源接口 + 板级适配 | 各 Board 分叉业务源码 | 优先同源 ASW，仅将特定 MCU 差异下沉 | 编译资源和测试证据 |
| 输出实现 | 只生成逻辑请求（当前） | 物理功率执行（未来） | **当前选逻辑模拟/隔离；实物输出禁止** | OD-04/07、危害分析、硬件保护与独立验证 |

**不可将“候选 A/B”理解为两个都要开发。** 选择应围绕实际产品覆盖范围、样件能力、资源占用、故障响应和 BOM 成本完成。

## 5. 系统级数据合同（结构字段为建议，不是已发布 ABI）

| 数据对象 | 建议核心字段及单位 | 生产者 / 消费者 | 失效/边界约束 | 追踪 |
|---|---|---|---|---|
| `BrakeInputSample` | 值/有效标志/来源/采集时间/故障原因 | BSW 接入 → ASW 输入质量 | 失效或过期不得等同松开/踩下状态 | `SYS-IN-001/003` |
| `MotionSample` | 纵向加速度或减速度、单位、坐标约定、时间戳、有效性 | 传感接入 → ASW Motion | 不使用未确定正负号、未证实的量程/数据单位 | `SYS-IN-002/005` |
| `BrakeConfig` | 重量档 ID、等级、schema 版本、有效性/校验状态 | 参数服务 → 控制/HMI | 保存不等于立即生效；恢复规则须明确 | `SYS-CFG-001…008` |
| `BrakeRequest` | 逻辑请求、禁能标志、计算依据、生成时间 | ASW Control → 执行抽象 | EVB 禁止绑定实际功率输出 | `SYS-CTRL-001…005`, `SYS-OUT-001/003` |
| `SystemStatus` | 阶段/限制/故障摘要/正在制动语义/时间戳 | SystemState → HMI/诊断 | App 不得以本地缓存冒充实时设备状态 | `SYS-DIAG-001…004` |
| `ParameterCommand` | 命令、请求 ID、操作参数、权限、状态、结果、回读 | HMI/通信 → 参数服务 | 乱序、重复、重试、超时不得假成功 | `SYS-COM-001/002`, `SYS-SEC-*` |

待 P2 批准后再冻结符号、单位、最大长度、版本兼容、线程/中断上下文和 ABI；不能根据这个概念表直接替换 SDK Driver API。

## 6. 状态与安全责任边界

系统级候选状态：`INIT`（启动/检查）、`INHIBITED`（未满足启用条件）、`READY`（输入、配置及安全许可可运行）、`ACTIVE`（有效制动请求处理中）、`DEGRADED`（受限运行，条件待危害分析）、`FAULT`（需明确故障处理）、`MAINTENANCE`（受控服务模式）。

这些是语义候选，**不是已经评审完的安全状态机**。特别要核对：初始化失败、参数损坏、传感器无数据、通信错乱、复位、低压、看门狗、执行器异常和异常恢复；不同故障与车辆工况可能要求不同动作。`READY` 更不能仅靠软件标志判断功率硬件具有安全准入资格。

**当前 EVB 强制硬边界**：`BrakeSystem_CanEnableBrakeOutput()` 在读取到的固件快照中返回 `false`，但该源码事实不能证明电气接口天然安全。实物接线与后续代码须继续保持无执行功率路径，任何意外输出都应视为阻塞问题。

## 7. 与现有云途板的接口核对

- 用户已确认 `YTM32B1LE0-EVB-LQFP64`；RevC 原理图为 5 页，RevA 评估手册 16 页，两份文件**并非同一已证实 PCB 修订**。
- 图纸 MCU 标注 `YTM32B1LE05H0VLHT`，RevC 有 PCN 新器件说明。必须核实 PCB 丝印、MCU 实物顶标和 SDK 精确版本；芯片型号不可只依据一个旧工程名决定。
- **可复核差异**：RevA 评估手册写板载 EEPROM PTD0/PTD1 为 I²C0；RevC 图纸/复用标注为 I²C1；在精确型号和 SDK PinMux 核对前不执行硬件写操作。
- UART1-USB 资料标 PTC8/PTC9；CAN 物理接口有 PTC6/PTC7 和 STB 信号候选；以上均须以实物和 RevC 电路图验证，不代表线已接通或定为产品最终复用。
- 不把 BMA510 厂商芯片手册当作模块板级接线图；不假定历史 WLT8016 文档就是实物手中蓝牙模块的固件 GATT 实现。

## 8. 配置模型与共用协议的权威位置

- `Variant`：产品功能矩阵（是否 App/LCD、可选功能、参数默认方案和可用操作），由产品批准控制。
- `Board`：MCU、PCB Rev、PinMux、供电与接口电气，必须有目标硬件证据。
- `Release`：软件源版本、编译链/SDK、接口版本、测试记录和发布标识。
- 组合有效性需要有明确规则，但不能强制其形成线性的 `Variant→Board→Release` 流水线。
- 固件与 App 共用的 BLE-ICD、参数 schema 和故障代码应**只维护一份有效合同**，避免两分支各写一套；合同内容候审后再决定其受控存放位置和变更流程，不擅自跨分支写入。
