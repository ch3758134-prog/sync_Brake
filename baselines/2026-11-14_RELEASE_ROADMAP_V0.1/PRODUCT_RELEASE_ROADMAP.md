## 一、负责人确认的三个连续产品版本

| 版本 | 角色 | 目标 | 核心验收特点 |
|---|---|---|---|
| Release-01（第一版） | 基础功能测试版 | 真实验证同步制动控制能驱动相关模块及完整工作链路，不是单纯 Host/Mock 演示 | 需要实际传感、制动输入、控制决策、受控输出/执行、故障反馈的分级证据；没有实物前只能完成框架与模拟，不称功能实测通过 |
| Release-02（第二版） | LCD 产品交付版 | 在第一版真实基础功能之上，比较完整地实现此前研究资料中的 LCD 产品使用功能 | 先实现 LCD 功能矩阵，经后续真实台架/车辆工况测试、产品需求补充与多轮整改，再完成交付验收 |
| Release-03（第三版） | 手机 App 智能版 | 在成熟的共用制动核心基础上增加 BLE/App 交互、配置、状态与诊断及已决定的智能能力 | 保持自动制动主机独立；以真实设备、统一参数语义和跨端协议的联调与验证为依据 |

**顺序约束**：App 不与 LCD 作为同批首发产品；LCD 是首个完整交付产品方向。可以提前研究共用协议/无线模块的可行性，但不因此提前宣布 App 产品版本实施或完成。发布版本正式号码尚未确定，此处 Release-01/02/03 仅为顺序代号。

## 二、Release-01 基础功能测试版范围

- 同步制动基本业务链路：制动意图输入 → 运动/减速度输入（按最终确定的传感路径）→ 主控制器可信判断与请求 → 执行接口 → 可观察的执行/故障反馈。
- 相关模块的真实功能验证：当前讨论的 CAN 加速度模块、UART/蓝牙通信等，是否属于首版必须的整机闭环组件要按实物与控制需求核实；即使无线模块先做功能测试，也不等于首版交付手机 App。
- 支持必要的测试、配置和诊断方式，测试版不要求拥有完整 LCD 外观、正式 App 或量产 PCB。
- 分层证据不可混用：系统模型/Host、Target Build、烧录、模块通信、受控台架执行、真实控制效果、故障注入均独立记录。
- **安全门槛**：当前开发板无已批准功率链。未来若需进行真实制动执行验证，须先完成功率硬件、供电、接线、默认态、故障关断和台架安全准入。禁止将“第一版必须驱动真实模块”解释为现在可以直接连接房车制动器上路。

## 三、Release-02 LCD 首个交付版本：按原始资料建立功能矩阵

从三份已读来源可以确定 LCD 方案的功能池如下。

| 功能领域 | 前期资料对 LCD 的描述 | 本次管理状态 |
|---|---|---|
| 基础制动 | 制动档按房车重量范围匹配；同档内调制动力；主机独立同步制动 | Release-02 核心 |
| 主屏 | 当前制动档、制动力等级、工作状态；出现异常优先突出故障 | Release-02 核心 |
| 本地交互 | 增加/减小高频直接操作；菜单选择、确认、返回；不依赖手机 | Release-02 核心 |
| 配置与持久化 | 首次设置、低速试车验证流程、配置保存、重新上电恢复 | Release-02 核心，具体保存生效策略遵循已批准 DD-06 |
| 故障显示 | 正常、制动中及制动线路、电源、过流/短路等故障信息；温度/限幅取决于硬件检测能力 | 基础诊断必需，精确故障可检测性随硬件确定 |
| 恢复默认 | LCD 菜单可操作；V2.6 标注“建议”，V3 将其列为设置菜单候选 | 交付范围待细化确认 |
| 显示偏好 | 亮度、语言等 | 原始资料标注可选 |
| 高级制动调节 | 起始/最小制动力、正向响应、倒车响应、Boost、简单/高级模式 | 原始资料功能池；纳入第二版与否需逐项确认 |
| 直接/特殊操作 | 手动独立制动、手动预设、停车保持、自动/手动模式 | 原始资料可选；涉及独立安全评估，不自动作为必须实现 |
| 多配置/高级管理 | 多套配置在 V2.6 中不建议作为 LCD 基础；软件升级也非 LCD 基础 | 不强行加入 LCD 主交付功能 |
| 侧摆稳定辅助 | V2.6/V3 明确作为增强能力候选 | 不以本次顺序决定自动纳入 |
| 实体设计 | 具体屏幕规格、按键数量、旋钮和外壳/安装方式由整机项目确定 | 正式 PCB/HMI 硬件未冻结 |

**执行顺序**：对照 V1.1、V2.6、V3 原始功能资料形成 LCD 功能映射 → 明确核心/增强/不纳入 → 实现 → 系统与实体测试 → 收集实际需求和变更 → 整改回归 → 形成完整 LCD 产品交付版。不能仅以“页面完成”判定可交付。

## 四、Release-03 App 智能版

- 继承相同的制动档、制动力、参数状态、故障和主机独立控制语义。
- 在产品共用业务合同下增加真实 BLE 连接、设备身份、命令回执、状态新鲜度与可能的配置管理、维护功能；具体增强范围按第三版产品决定。
- App 的无线断线或手机缺席不得成为实时同步制动的必要控制条件。
- 不应因开发第三版复制或分叉制动核心，Variant、Board 和 Release 仍相互独立。

## 五、当前实际研发状态（PCB 尚未完成）

4. 模块和整机的验证分层、后续真实测试准入；
5. 产品范围、制动器参数、供电、性能与安全分析继续留作真实证据驱动的待决项。

不以目前已有 GitHub 固件/App 源码作为基线；不提前进入它们的清理、保管或复用。不把开发板当作正式 PCB 已完成。

## 六、与 P0–P8 和配置管理的关系

- `P0–P8` 是工程研发阶段与对应方案/验收管理，不是八个产品版本。
- 已批准 `P8 R0–R2` 是研发样件、工程样机、受控产品发布的**成熟度/准入分级**，不是本次 Release-01/02/03 产品版次。两套维度可以并存，不得混用。
- `Variant` 管产品功能配置，`Board` 管实际 MCU/PCB，`Release` 管某次受控产品软件/整机发布；三者继续独立。
- 原“LCD/App 并行可扩展”的架构原则保持有效，**产品发布顺序**按负责人新指令确定为测试版 → LCD 版 → App 版。
- 若此前 P3/P4 文件或执行台账将 App/LCD 理解为同一批次首发，以此文件的最新负责人指令为准；不篡改已归档的历史原文。
