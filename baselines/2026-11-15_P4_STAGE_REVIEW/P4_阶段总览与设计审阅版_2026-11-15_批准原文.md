## 1. P4 整机基本设计（已批准的方向）

### 1.1 系统功能与控制权

主控制器 ECU 是自动同步制动的业务决策主体；V2 LCD、V3 BLE/App 负责受控的参数操作与状态显示，不能成为实时制动功能运行的必要在线条件。与 P3 的 SF-01～09 功能分配一致：系统供电与初始化、制动意图、运动信号、控制决策、实际执行、参数管理、故障诊断、人机交互、版本/维修服务各有独立责任。

### 1.2 关键边界（不是电气原理图）

```text
牵引车/驾驶员制动意图 ─→ 车端输入及有效性 ─┐
                                             ├─→ 主控逻辑制动请求
拖挂真实纵向运动 ──────→ 运动传感与质量 ───┘           │
                                                       ▼
设备配置、系统状态、故障事实 ───────────────────→ 执行许可判断
                                                       │
                               真实物理保护/功率驱动/供电回路
                                                       │
                                 线束 → 轮端电制动器 → 机械效果

                       诊断/状态 → LCD（V2）/ BLE-App（V3）
```

**五个不可混为一谈的事实**：意图/输入可信 → 逻辑请求合法 → 物理执行许可成立 → 输出电气行为实际发生 → 轮端机械制动确实实现。当前硬件的后三级仍无对应可宣称通过的实物证据。

### 1.3 V1 / V2 / V3

| 产品版本 | 阶段目标 | 本轮状态 |
|---|---|---|
| V1 | 基础功能测试：制动输入/运动/控制、状态诊断、参数、必要实物通信；未来安全准入后才进入真实执行链测试 | 系统目标已定；新工程与实测未完成 |
| V2 | 具备 LCD/按键的首个产品交付形态，沿用共用控制核心 | 产品设计方向已定，实体 LCD/PCB 尚未定 |
| V3 | 增加 BLE 和 App 交互，不另建一套制动控制算法 | 软件业务方向已定，App 不参与实时闭环 |

## 2. DD-01～DD-08：P4 系统合同全貌

| 合同 | 已经建立的设计规则 | 仍未冻结 |
|---|---|---|
| **DD-01 产品适用包络** | 首版优先电控制动器拖挂式房车；只有具有证据的车型/制动器组合才能宣称适用 | 市场、车辆类别、质量、轴数、轮端数量及电气范围 |
| **DD-02 制动意图/运动输入** | 输入来源、物理单位、方向、时间、新鲜度及故障必须能区分；运动信号不天然等于驾驶员制动意图 | TRIG / MOT 具体物理来源与主辅关系、阈值、报文、安装 |
| **DD-03 制动请求/执行许可/反馈** | 逻辑请求≠硬件许可≠功率电流≠轮端效果；EVB 禁真实制动功率 | 功率拓扑、实体默认态、独立保护、反馈覆盖和故障动作 |
| **DD-04 系统状态与故障** | INIT/INHIBITED/READY/ACTIVE/DEGRADED/FAULT/SERVICE 是对外业务状态语义；不能把故障一律当作应立即清零输出 | 故障等级、动作时限、锁存/恢复和实际制动力后果 |
| **DD-05 KPI 与时间预算** | 按端到端起止事件、工况、最坏情况、测点和测试方法分解 KPI-03～05/07/09/10 | 毫秒、电流、电压、热、轮端效果等数值 |
| **DD-06 重量档/制动力参数** | 重量档与微调独立；区分 RECEIVED/VALIDATED/ACCEPTED/EFFECTIVE/PERSISTED/READBACK_CONFIRMED | 档数、适用重量区间、1～10 是否定版、默认值、标定映射、行驶中调参规则 |
| **DD-07 危险与验证追踪** | P3 的 HA-01～12、SG-01～08、SSR-01～18 与系统责任、分层测试关联 | 正式 HARA/FMEA、残余风险、实体安全证据 |
| **DD-08 Variant/Board/Release** | 产品功能配置、硬件平台和软件发布版本分开管理 | 实体制造身份、协议兼容和具体生产/服务策略 |

DD-01～08 来自 P4 系统级合同和后续专题详化。部分初稿曾标为候审，具体审批效力以对应批准记录和集中审批方案为准；**没有任何 P4 合同意味着功率安全已经验收**。

## 3. 物理接口、PCB 和安全

### 3.1 SYS-IF-01～08 外部接口清单

| ID | 接口 | 目前最关键的未决事项 |
|---|---|---|
| SYS-IF-01 | 牵引车制动触发 | 真实来源/极性/电压/线束/短断路可检测性 |
| SYS-IF-02 | 运动信号 | 真实模块型号、安装方向、单位和采样时序 |
| SYS-IF-03 | 逻辑与功率许可边界 | 物理门控、复位、执行禁止和错误传播 |
| SYS-IF-04 | 制动器负载 | 轴数/各轮线圈、电热定额、线束，**BLOCKED** |
| SYS-IF-05 | 执行反馈与保护 | 哪些电流/电压/状态真能测到、诊断盲区，**BLOCKED** |
| SYS-IF-06 | 人机、维护、App | 设备权威状态/命令权限/数据新鲜度；非实时控制权 |
| SYS-IF-07 | 车端供电及接地 | 电源和瞬态、电气保护、复位行为 |
| SYS-IF-08 | 应急/驻车/脱挂接口 | 与原车独立装置的安装及法规边界，**BLOCKED** |

### 3.2 PCB-01～13 设计输入

| 编号范围 | 要求主题 | 当前约束 |
|---|---|---|
| PCB-01～03 | 电源、制动触发前端、运动传感器接入 | 车端接口/供电/模块身份待核对 |
| PCB-04～07 | 轮端负载、复位默认态、实体输出许可、保护反馈 | **缺轮端规格及安全论证，功率实施阻断** |
| PCB-08 | V1 无功率隔离测试口与测量 | 可开展测试规划；实物条件须独立核对 |
| PCB-09～11 | LCD、BLE、调试/烧录/生产服务 | 未来 Variant/Board 的配置和设计选项 |
| PCB-12～13 | EMC/热、电源域隔离、应急/驻车/脱挂 | 真实负载、安装及整车安全依据待到位 |

**当前并未选定**：TRIG-A～D、MOT-A～C、PWR-A～C 的某一具体硬件架构；开发板不是量产 PCB，BMA510 手册也不能证明它与某个外置 CAN 运动模块相同。

### 3.3 功率安全责任 SAFE-01～07 / SP-01～08

目前已批准的是**未来必须回答的问题与需取得的证据**：上电/高阻/复位时真实物理状态、MCU 卡死后独立保护的实际效果、MOSFET 等功率器件故障、支路/总电流监测盲区、独立应急制动/驻车的关系、不同工况的故障响应，以及台架隔离/限能/急停。

`FC-01～12` 描述失效从输入、传感、配置、MCU、功率级、线束/轮端、供电到人机的传播与盲区；`SP-01～08` 指定保护问题的责任主体；`TV-01～18` 是未来验证用例目录，**全部为计划而非 PASS**。不可用“软件 PWM=0”或“有看门狗”证明功率器件短路和制动无法释放已被安全控制。

## 4. P4 完成门槛：哪些能推进，哪些仍阻断

| 工作内容 | 现在的决策 | 理由 |
|---|---|---|
| Host 纯逻辑测试、配置事务、故障状态模拟 | **可在单独受控任务授权后开始** | 不依赖真实轮端功率电路 |
| 云途 MCU / Keil / 官方 SDK 环境核验、基础 GPIO / Timer / UART / CAN | **可在确认实际平台后逐项启动** | EVB 与真实制动功率完全隔离 |
| BMA510 或外置 CAN 运动模块、WLT8016 通信的独立模块试验 | **条件允许** | 需要准确的实物身份、协议和引脚资料；不误认为已检验 |
| 主控制业务无功率执行模型 | **可继续设计、实现与 Host/EVB 受控测试** | 逻辑请求和物理许可严格分开 |
| 正式功率 PCB 的选型、热/过流定额及失效策略 | **阻断** | 缺负载/车端事实、原理图与危险分析 |
| 实际轮端制动功率台架、道路试验 | **禁止提前开展** | 独立保护、实验台/风险审批、符合性证据未完成 |

**P4 当前结论**：设计框架、接口合同和未来硬件/安全验证清单已经达到足以支持**受控并行启动非功率软件开发**的程度；但不能认定 P4 整体结项或支持真实功率硬件安全释放。

### 产品事实集中缺口 C-01～06

C-01：市场/车型/重量/轴数；C-02：真实制动器与电气/线束；C-03：车端触发与运动来源；C-04：V2 LCD 产品形态；C-05：重量档及制动力标定/保存/工况；C-06：Boost/手动/倒车/OTA/侧摆等增强功能的版本归属。需要证据支持时再一次性集中决策，不因这些暂未确定而阻止无功率测试。

## 5. 软件阶段交接建议（基于现有 P4 的下一步，不是已执行事实）

**SW-00：真实板卡与开发环境核验**：准确 MCU 型号/开发板 Rev、官方 SDK/Pack/启动文件、Keil 版本与配置、下载器、现有可重复编译/烧录条件；不拿旧仓库工程当新基线。

**SW-01：全新无功率固件工程**：明确 ASW/BSW、BoardCfg 和基础服务职责，建立全新受控工程、启动/复位与安全输出隔离规定，做 Target Build 和基础板测。保持主函数简洁、代码可读、注释清楚，严格区分 Host/Target/实物证据。

**SW-02：非功率驱动与模块联调**：GPIO/定时器/UART DMA/CAN、真实加速度模块、蓝牙模块，基于实物/SDK核验后逐项实施和保存日志。

**SW-03：制动逻辑验证**：意图/运动数据质量、参数管理、故障与控制策略，所有制动力输出仅在虚拟或物理隔离状态下观察。

Codex 的实际执行另须明确文件范围、禁止修改项、测试标准、提交路径和失败处理。V1 不应以在旧仓库中找到的实验源码视为正式的已完成工作。

## 6. 阶段实情与审批建议

- **已确认**：架构设计原则、V1→V2→V3 路线、P4 系统/PCB 接口输入、物理候选研究、外部接口及故障保护/测试计划已获得相应设计层次的批准。
- **未完成**：实际车辆/制动器/供电规格及目标市场；正式产品原理图核对；HARA/FMEA与独立保护论证；功率/车辆实测；新固件 Target Build 与开发板实测。
- **现在推荐**：无需再增加同类概念性 P4 文件；让 P4 实体硬件与产品安全工作保持 `OPEN/BLOCKED`，并优先授权 **SW-00 → SW-01** 非功率工程任务，以新的构建、烧录及模块实测结果推进。
- **没有请求**：本审阅汇总不额外要求重新批准已有设计，也不请求授权制动功率或 P4 阶段整体结项。
