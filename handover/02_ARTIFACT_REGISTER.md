## E. 登记准入与更新规则

1. 任何新文件产生时**同一任务内**登记：唯一 ID、文件名、GitHub 路径、版本、来源版本、Git SHA/校验和、责任人、编制人、接收人、批准状态和证据级别。
2. 二进制测试证据可存放 GitHub 受控附件、受批准的制品仓库或受访问控制的供应商资料区；GitHub 中必须留下不可混淆的定位信息与 SHA-256。**只记录本地路径不算已交付。**
3. 若某项文件暂不可入库，登记 `MISSING`/`RESTRICTED`、原因、唯一责任人和解除条件；不可标记 `HANDED_OFF`。
4. 每个交接单必须由接收方核对文件、版本、可读性、适用性与未决问题后，才能把 `SUBMITTED` 变更为 `ACCEPTED`。
5. 上游修订必须新建版本和影响分析，不改写已批准的原版内容；`APPROVED` 与 `TEST_PASS` 分开管理。
