## 1. 本轮直接形成的三个工程结论

1. **同源控制核心**：V1/V2/V3 共享制动意图判定、运动质量评估、控制决策、参数校验、诊断与系统状态的业务语义。LCD/App 是用户交互和外部接口 Variant，不形成第二套实时制动算法（`BASELINE`）。
2. **V1 要有真实证据**：V1 的最终目标是相关真实模块与受控制动执行链路工作，不能以 Host 模型、通信演示或“PWM 波形存在”替代。由于 PCB/功率硬件未完成，当前先实现架构和测试合同；未来分级验证，各级测试必须分别记录（`BASELINE`）。
3. **PCB 设计必须从系统要求出发**：先定义输入、运动、供电、功率执行、硬件保护、反馈、调试和测试隔离要求，再根据制动器与车辆参数选型和确定电路。不能用开发板现有接口倒推最终产品能力（`BASELINE`）。

## 3. 系统功能结构与责任边界

### 3.1 功能链（逻辑层，非接线图）

```text
牵引车制动意图 ──> 输入信号质量 ──┐
                                   ├──> 同步制动业务决策 ──> 逻辑制动请求 ──> 执行准入/约束 ──> 功率执行硬件 ──> 轮端制动器
纵向运动信息 ────> 方向/单位/时效 ──┘                                    │                    │                     │
                                                                         └──────状态/诊断/反馈<───────┘
                     参数管理（重量档、制动力、适用配置）──────> 业务决策
                     LCD / App / 测试界面 <──────> 参数、设备状态、故障、版本（非实时控制必需）

                     车辆电源 / 线束 / 独立硬件保护与实际制动执行链：需要后续实物论证
```

**必须区分五个事实**：控制器形成逻辑请求、准入允许、功率级收到命令、可测实际电流/输出、轮端产生制动作用。这些事实彼此不能自动等同。

### 3.2 稳定的系统模块边界（不规定代码目录或 SDK API）

| 模块代号 | 对应已有功能 | 输入/输出合同 | 异常责任 | 实现阶段 |
|---|---|---|---|---|
| SYS-M01 运行资格 | SF-01 | 电源/复位/配置/必要输入状态 → 就绪与限制原因 | 初始化不完整、重启、欠压 | V1 起 |
| SYS-M02 制动意图 | SF-02 | 物理制动触发 → 意图值、可信度、有效性、更新时间 | 丢失/冲突/抖动/接线错误 | V1 起 |
| SYS-M03 运动测量 | SF-03 | 传感器原始信息 → 纵向物理量、方向、单位、时间、质量 | 过期/错误方向/超量程/通信故障 | V1 起 |
| SYS-M04 控制决策 | SF-04 | 有效输入+配置+运行资格 → **逻辑**请求、受限原因 | 非法输入、标定不适用、边界值 | V1 起 |
| SYS-M05 执行与保护边界 | SF-05 | 请求+执行准入 → 实体功率链；反馈/故障 → 状态 | 驱动失控、开短路、热、无法释放 | V1 后期，仅安全台架准入后 |
| SYS-M06 参数与存储 | SF-06 | 配置变更请求 → 校验、受理、生效、保存、读回 | 版本不兼容/写失败/掉电 | V1 起，V2 用户化 |
| SYS-M07 状态与诊断 | SF-07 | 系统事实/反馈 → 权威状态与故障/时间有效性 | 显示误判、信息陈旧、恢复误报 | V1 起 |
| SYS-M08 人机交互 | SF-08 | LCD、未来 App 或研发诊断手段 ↔ 参数/状态合同 | 离线、错误设备、误操作 | V1 简化；V2 LCD；V3 App |
| SYS-M09 身份维护 | SF-09 | 产品/Board/Release 身份、故障/安装检查 → 维护信息 | 版本错配、错误配置 | V1 起 |

**跨层原则**：ASW 承担控制业务与状态语义；BSW 提供硬件适配和基础服务。当前不依据未核实的 SDK 能力决定 Driver/Service/MCAL 具体数量、引脚或中断设计，也不让 LCD/App 直接修改内部控制状态。**此原则来自已批准体系；模块表属于本稿进一步细化建议。**

## 4. 系统接口最小合同：设计输入而非通信协议

| 接口 ID | 生产者 → 消费者 | 业务数据 / 状态 | 必须考虑的无效情形 | 待实物证据 |
|---|---|---|---|---|
| ICD-01 | 牵引车制动输入 → SYS-M02 | 制动意图、有效性、变化依据 | 无信号、噪声、断短路、异常电平、非制动误触发 | 制动触发真实来源、物理电平、电气保护、接线方式 |
| ICD-02 | 运动传感器/模块 → SYS-M03 | 纵向量、方向、单位、时刻、质量 | 超时、安装反向、超量程、通信异常 | 实际模块身份、封装接口、安装位置和数据格式 |
| ICD-03 | SYS-M02/M03/M06/M01 → SYS-M04 | 意图、运动、合法配置及运行许可 | 无效/过期/不一致数据 | 失效策略、控制律、各输入主辅关系 |
| ICD-04 | SYS-M04 → SYS-M05 | 逻辑制动请求、限制与状态 | 不可信请求、过大/过旧请求、配置未准备 | 电流/PWM 等最终执行语义、功率能力和安全许可 |
| ICD-05 | 功率级/轮端 → SYS-M05/M07 | 可测执行量、状态与故障 | 电流异常、关断失败、传感失效、线束/轮端故障 | 电路监测能力、轮端及线束拓扑 |
| ICD-06 | 参数/诊断 ↔ LCD（V2）/App（V3） | 变更事务、配置版本、状态/故障、时间有效性 | 断链、重复、非法值、状态过期、错误设备 | LCD 实体方案、后续 BLE 通信协议 |
| ICD-07 | 车辆电源/安装维护 ↔ 系统 | 供电、复位、兼容性、隔离、设备身份 | 反接、跌落、瞬态、维修误接 | 车型/电源和安装标准 |

**接口质量约束（提案）**：涉及决策的输入必须可区分**值、质量/有效性、时间来源**；涉及设置的响应必须可区分**收到、校验、受理、生效、保存、读回**；涉及故障的显示必须可区分**设备健康状态与通信可见性**。具体单位、超时、序列号和编码方式在源证据确认后再冻结。

### PCB 设计输入的交付门槛（提案）

- **可先确定的**：系统需要哪些输入、诊断、独立保护和调试能力；电气接口需要覆盖哪些正常/故障场景；哪些端点要能在台架上观察。
- **必须等待材料的**：电压/电流/功率/热设计定量指标、制动器与车端连接标准、硬件故障动作、保护器件设计、目标市场适用性。
- **不允许跳过的**：上电、复位、程序失控、供电异常、输出器件失效时的**实体功率行为**审查；只有软件层面禁能不构成实体安全证明。
