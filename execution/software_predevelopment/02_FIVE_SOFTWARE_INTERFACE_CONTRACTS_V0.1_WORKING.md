## 1. 公共数据合同：任何参与控制的数据必须可审计

| 契约字段（概念名） | 用途与必要条件 | 来源/检查方 | 当前冻结状态 |
|---|---|---|---|
| \`source_identity\` | 唯一标识接线/设备实例/输入信号的实际来源，不能由通信端自动伪造可信身份 | BSW Device/Board + ASW信号验证 | 字段语义 DESIGN_PROPOSED；编码 OPEN |
| \`data_type_and_unit\` | 表明物理量类别、单位、数值表示和精度；禁止隐含单位换算 | 设备层归一化、ASW消费者审查 | 单位集合 OPEN |
| \`value\` | 测量或业务值，只有明确有效性时能参与正常控制推导 | 采样生产者 | 物理范围 OPEN |
| \`quality\` | 独立表达未取得、可用、无效、矛盾、超范围、未标定等原因 | 设备/输入质量模块 | 语义必需；实现枚举 DESIGN_PROPOSED |
| \`sample_time\` | 物理采样或能证明的近似采样时间，和接收时间不同；若无法获知应明确质量限制 | Device/BSW | 来源/精度 OPEN |
| \`receive_time\` | 系统接收到帧/采样的单调时间 | BSW Signal Gateway | 精度/上限 OPEN |
| \`sequence_or_revision\` | 数据代次/顺序，识别重复、重放、乱序或复位后的旧帧 | 设备/BSW | 是否原生支持 OPEN；不能伪称设备有序号 |
| \`boot_epoch\` | 区分设备/主控重启前后的代次，避免误比较新旧时标 | BSW/系统启动 | 具体持久化或递增机制 OPEN |
| \`reason_code\` | 数据被拒收、降级、超时、错误的可诊断原因 | ASW | 分类方案 DESIGN_PROPOSED |
| \`producer_version\` | 源协议/配置/板卡能力版本可追踪 | 身份/Variant模块 | 具体编码 OPEN |

### 1.1 质量、新鲜度、可用性必须独立

- **新鲜度**：由经定义的单调时基、可追溯采样时刻和消费时刻判断。不能只凭“刚收到一个包”断定采样新鲜。未能提供真实采样时刻时，需分析接收时间与传输延迟的误差边界。
- **有效性**：表示身份/单位/范围/协议/标定与一致性满足当前控制要求；\`valid=false\` 不等价于数值零，更不等价于“没有制动意图”。
- **来源真实性**：字段存在不等于可信，特别是 BLE/测试输入与车端输入不得无授权共享可信来源等级。
- **可用性**：当前运行资格、传感器质量、设备身份和功能 Variant 共同决定能否被特定消费者使用；数据“有效”不代表整个制动系统已经 READY。
- **数据冻结**：数值不变不一定代表故障；必须结合协议心跳、样本序列、传感器自检或动态场景证据判断，不能用“连续 N 次相同”无依据判故障。
- **同步快照**：参与同一次控制决策的数据需带版本/时刻和已定义的一致性条件；不同时间的意图、运动与参数不应被静默拼为“同时有效”。同步阈值及可接受组合由系统时序预算确定。

### 1.2 错误处理最小共同约定（设计建议）

- 对外诊断应有**错误源、当前是否活动、发生代次/时间、原因及验证过的恢复依据**；不能只有布尔 \`fault\`。
- ISR/ DMA/任务之间的数据交接必须在未来设计中明确所有权、竞争和栈/缓冲上限；本文件不假定某种 MCU 原子指令、缓存机制或 RTOS。
- 可观测不等于可解除：HMI 清除显示记录，不应替代设备端故障恢复。
- 所有逻辑“许可”判断不得自行宣称真实硬件安全，具体输出安全动作是系统硬件共同职责。

## 2. SW-ICD-01｜制动意图接口

| 字段 | 设计合同 |
|---|---|
| 上游生产者 | 真实牵引车制动意图来源 → 采样/通信驱动 → BSW信号网关 |
| 数据责任 | ASW-01 \`brake_intent\` 负责身份/信号质量、去抖依据、时间有效性与矛盾诊断 |
| 下游消费者 | ASW-03 \`control_core\`、ASW-04运行资格、ASW-07诊断 |
| 数据语义 | **意图值**与**值是否可信**分别存在；可能是布尔、程度或其他信号，具体类型 OPEN |
| 时序语义 | 采样/接收/判定时刻可解释；丢失、超期或时钟异常可诊断 |
| 失效情况 | 断线、短路、极性误接、抖动、冲突、过期、重复/旧数据和信号无法判断 |
| 禁止行为 | 不将“信号不可用”暗中转成“有效无制动”；不把“有减速度”当作驾驶员已制动 |
| 安全追踪 | SSR-02/03/05/09/18；HA-01/02/04 |

**消费合同（DESIGN_PROPOSED）**：ASW-03 获取的是包含 \`intent_value/quality/time/source\` 的意图**快照**；读取后先校验质量和资格，再交给策略处理。发生异常应报告事实、原因、时刻与未决策略，不在本接口中擅自决定实际轮端失效制动力。

**必须先取得的外部依据（OPEN）**：牵引车制动意图从哪里来、接线电平/协议/极性、电气隔离与保护、信号变化时限及适用工况、断短路可检测能力。

## 3. SW-ICD-02｜运动信息接口

| 字段 | 设计合同 |
|---|---|
| 上游生产者 | 实际运动模块/传感芯片 → DEV-01 CAN协议**或** DEV-02 BMA510总线协议（两者身份尚未证实为同一设备） |
| 设备层责任 | 按真实协议完成帧/寄存器校验、单位换算及方向来源保留，不向ASW泄漏原始协议字段 |
| ASW责任 | ASW-02 \`motion_signal\` 负责纵向运动语义、安装/坐标质量、新鲜度、饱和/异常诊断 |
| 下游消费者 | ASW-03控制决策、ASW-04运行资格、ASW-07诊断 |
| 数据语义 | 纵向加速度或减速度的**带单位**值、坐标符号、采样时间/质量；不能默认某轴或正负号 |
| 失效情况 | 协议错帧/丢帧/乱序、设备复位、方向颠倒、安装角度、饱和、零偏/未校准、时间戳不可用、通信超时 |
| 禁止行为 | 未知方向/单位时不推导控制幅值；仅有效运动变化不证明存在制动意图 |
| 安全追踪 | SSR-02/03/05/09；HA-02/04/09 |

**分层决策**：CAN控制器驱动只负责帧/错误/时戳；CAN运动模块设备层才解释报文；ASW层判断“该物理量能否参与本轮同步制动逻辑”。若真实硬件最终使用 BMA510，须走相应 I²C/SPI 设备路径；不凭一个厂商芯片 PDF 虚构外置 CAN 模块的字节序/标识符。

**待证据确认（OPEN）**：实际模块型号、接口、输出速率、单位/坐标约定、有效范围、自检、采样与传输延迟、上电稳定性和安装姿态确认方式。

## 4. SW-ICD-03｜控制输入快照与逻辑请求接口

### 4.1 输入口：ASW-03 只接受“带资格的完整快照”

| 输入组 | 来源 | 需要可区分的事实 |
|---|---|---|
| 意图快照 | ASW-01 | 来源、值、有效/过期/矛盾、时刻 |
| 运动快照 | ASW-02 | 单位、方向、质量、时间、标定/安装状态 |
| 当前有效配置 | ASW-06 | 重量档/制动力/标定适用性、有效版本、提交状态 |
| 系统运行资格 | ASW-04/05 | INIT/INHIBITED/READY/ACTIVE/DEGRADED/FAULT/SERVICE的系统语义、限制原因 |
| 故障摘要 | ASW-07 | 活动故障、诊断能力边界和恢复要求 |
| 运行时基 | BSW-S01 | 当前单调时间、重启代次、时基可信状态 |

**一致性约束**：一轮控制计算只应消费**一致性受控**的快照或明确处理不同步的质量状态。参数在决策过程中改变时必须有可验证版本边界，不能出现部分字段来自新标定、部分字段来自旧标定的混合快照。

### 4.2 输出口：不是物理 PWM / 电流命令

| 逻辑字段 | 含义与限制 |
|---|---|
| \`request_identity\` | 当前逻辑请求的可追踪身份，便于跨接口记录与去重 |
| \`request_value\` | 所期望制动作用的**逻辑量**；数值域、单位、上下限和映射依据待标定（OPEN） |
| \`request_quality\` | 该请求是否按已定义输入、配置和状态生成 |
| \`source_snapshot_revision\` | 说明是哪一版意图、运动与配置/状态生成的请求 |
| \`decision_time\` | 生成时刻；可追踪到输入采样，便于将来计算时延 |
| \`validity_window\` | 请求允许被后级视为新鲜的时限，具体最大值待时序分析 |
| \`constraint_reason\` | 限制或拒绝理由，可连接诊断与界面状态 |
| \`algorithm_revision\` | 控制逻辑/标定版本，不能和Board/Variant混为一谈 |

**约束**：本接口必须区分“无有效请求”“当前要求制动作用很小或为零”和“请求因异常无法判断”。最终异常时采取何种物理动作不是软件接口单独决定。按 V1 的无功率开发板验证要求，逻辑请求只能交给受控观测/测试通道，不接真实制动功率。

**安全追踪**：SSR-01/02/03/04/05/09/10/16/18，HA-01～05/09。

## 5. SW-ICD-04｜逻辑请求 → 执行许可 → 执行反馈

### 5.1 五级事实分离

| 层级 | 责任边界 | 当前可以判定什么 | 当前不能宣称什么 |
|---|---|---|---|
| A 意图证据 | SW-ICD-01 | 车端输入是否可信 | 车轮需要多少真实力矩 |
| B 逻辑请求 | SW-ICD-03 | 控制业务期望的逻辑制动作用 | 真实 PWM、电流或轮端力矩已存在 |
| C 执行准入/许可 | ASW-08+系统/硬件安全 | 许可因素、拒绝原因、状态 | 单一软件布尔值能证明物理安全 |
| D 驱动命令/实体功率 | 未来功率硬件与受控驱动 | **当前 BLOCKED**；只有将来设计及实物审查后明确 | 现有 EVB 能安全驱动实际拖挂制动器 |
| E 执行反馈/实际作用 | 未来采样、电流与轮端系统 | 当前可定义需要哪些反馈证据 | 真实电流已测、刹车力矩与命令一致 |

### 5.2 未来接口需保留的可观测项目（非当前物理实现）

\`logical_request_id\`、\`logic_eligibility\`、\`hardware_readiness\`、\`authorization_status\`、\`inhibit_reason\`、\`command_revision\`、\`feedback_available\`、\`observed_driver_state\`、\`feedback_time\`、\`fault_observation\`。

- **当前开发板**：\`physical_output_permission = NOT_AUTHORIZED\` 是外部研发/硬件准入约束，**不允许任何 SW 值、测试命令、蓝牙或维护模式解除**。在无功率验证中只能记录逻辑请求和测试观测结果。
- **未来产品**：输出禁止/使能、上电/复位/棕断默认电气状态、限幅/功率保护、实际短路/开路/持续通电的检测/响应能力，需结合硬件和场景分析另行明确。
- **诊断权限**：执行反馈不存在、丢失或超时必须表达“不可观测”，不能用“没有错误标志”虚构“实际制动力正常”。
- **失效动作**：哪种故障需要断开、维持、限幅、报警，必须通过车辆工况风险分析决定，**不可把全部故障统一定为软件输出清零**。

**安全追踪**：SSR-01/04～09/14/15/18；HA-01～08/12。硬件安全与车辆验证均未完成。

## 6. SW-ICD-05｜状态、诊断与配置/HMI接口

### 6.1 三类权威事实

| 信息域 | 权威来源 | LCD V2 / App V3 消费约束 |
|---|---|---|
| 当前生效配置 | ASW-06 + 已认可配置快照 | 显示设备**实际生效值**与版本，不以界面待编辑值顶替 |
| 已可靠保存配置 | ASW-06 + BSW-S02 持久存储确认 | 保存失败需独立可见；重启后读回才可确认恢复结果 |
| 运行/故障状态 | ASW-05/07 权威状态、事件及诊断 | HMI 必须区分设备状态、通信可见性、数据新鲜度；断联不能持续显示“设备正常” |

### 6.2 配置命令的事务证据和结果

| 阶段 | 设备端需要能作出的证据断言 | 不能被当作 |
|---|---|---|
| \`RECEIVED\` | 完整请求已到达受控入口 | 参数合法 |
| \`VALIDATED\` | 设备完成类型/范围/身份/版本/权限/适用性形式检验 | 已接受执行或已生效 |
| \`ACCEPTED\` | 设备按当时适用工况允许受理变更 | 已实际切换或保存 |
| \`EFFECTIVE\` | 设备生效快照版本已切换 | 可靠保存完成 |
| \`PERSISTED\` | 已确认满足相应持久化规则 | HMI已完成读回 |
| \`READBACK_CONFIRMED\` | 请求方获取且比对设备的有效/已保存版本 | 实车制动标定已得到验证 |

这些是**可能独立存在的证据事件**，不是强制按固定顺序执行的六状态自动机。生效/持久化先后依参数种类和安全分析确定；不得因为把表写在这里就假设“允许行驶中调参”。

### 6.3 参数变更最小输入与结果

- 输入语义：\`device_identity\`、\`request_identity\`、\`source_role\`、\`target_parameter\`、\`proposed_value\`、\`expected_config_revision\`、\`request_context\`。
- 输出语义：\`decision\`（接受/拒绝/未知）、\`reason_code\`、\`effective_revision\`、\`persisted_revision\`、\`current_authoritative_value\`、\`status_observed_time\`。
- \`request_identity\` 应支持辨别相同请求重传、旧会话请求和新请求；具体重放保护/安全认证机制需要网络安全设计，不预先选算法。
- **权限及运行条件**：V1研发诊断、V2实体按键、V3 BLE App 的授权来源不同，用户能否改关键参数、何时可改、是否需要再次确认，在安全分析和产品要求后批准。
- **故障处理**：非法值明确拒绝且不改变已生效配置；通信断开/超时明确“结果未确认”；不以重新连接覆盖保存失败或读回不符；维护恢复操作不可默默清空安全标定。

### 6.4 诊断事件生命周期（候选）

\`DETECTED → ACTIVE → (RESOLVING / LATCHED / PENDING_VERIFICATION) → CLEARED_WITH_EVIDENCE\`。

此处是**设计讨论用的可追踪生命周期**，不意味着故障均可自动恢复。每个故障的锁存、解除、告警和物理动作都要指定适用工况与责任人。应区分：传感器故障、输入异常、参数故障、时基失效、执行不可观测、供电、无线断链和界面状态过期。

### 6.5 HMI 与实时控制的边界

- LCD、BLE 和 App 是人机交互/配置/状态**消费者**；不能成为自动同步制动实时计算的必要依赖。
- HMI断联、状态过期时明确表述连接/时间不确定，不能报正常。
- 即使远端状态订阅失败，主控制器的故障诊断和运行资格判断仍是设备本地责任。
- 显示故障“已清”必须依据设备端诊断证据，不因关闭弹窗或清理手机缓存就当故障解除。

**安全追踪**：SSR-10/11/12/13/16/17；HA-03/10/11。

## 7. 跨接口交互与优先处理规则（不能越权冻结实体动作）

| 事件 | 输入/数据事实如何处理 | 必须传播至 | 物理动作是否已定 |
|---|---|---|---|
| 上电/复位 | 记录启动代次、时基/配置资格；旧时标不能伪作本次有效 | 资格、状态、诊断、控制输入 | **未定**；EVB仅无功率 |
| 意图失效而运动有效 | 意图明确不可用，不得由运动自动“补造意图” | 运行资格、控制策略待决、诊断 | 未定；须分析制动工况 |
| 运动数据错误方向/失效而意图有效 | 标记运动不可用及原因，不隐式参与正常运算 | 运动质量、资格、诊断、受限策略待决 | 未定；须分析降级 |
| 时间异常/过期 | 被消费快照不能被静默当作最新值；上报时基/新鲜度原因 | 输入/控制/资格/诊断 | 未定 |
| 配置校验失败 | 不将损坏配置加载为已认可生效参数；保留故障原因 | 参数、资格、诊断/HMI | 未定；禁止绕过产品安全条件 |
| 命令重复/断联 | 关联原请求身份与生效/保存版本，读回不能由缓存代替 | 参数、通信状态、HMI | 不影响本地实时控制决策职责 |
| 设备故障但 LCD/App仍显示缓存 | 权威状态与可见性/时效独立报告 | HMI 状态、诊断 | 故障真实处置待分析 |
| 功率反馈不可用 | 不以“未收到故障”作为实际功率成功证据 | 执行资格、诊断、状态/HMI | **BLOCKED**；需实际硬件 |
| 用户申请 SERVICE | 判断身份/工况/设备当前限制；不能绕过输出禁令 | 运行资格、配置、诊断 | **当前研发平台不授权功率** |
