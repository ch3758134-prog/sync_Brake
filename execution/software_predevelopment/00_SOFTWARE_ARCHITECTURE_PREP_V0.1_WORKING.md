**编号**：`BS-SW-PREDEV-001`  
**日期**：2026-11-14  
**状态**：`WORKING / DESIGN_ONLY / NOT_APPROVED_AS_DETAILED_IMPLEMENTATION`  
**上游批准依据**：`BS-P0P8-BASELINE-003 V0.3`、`BS-SW-STD-001 V1.0`、P4 DD-01～08 V0.2、P4 共用系统框架与 PCB 输入 V0.1 工作稿。  
**本轮目标**：把软件模块、依赖和接口、工程架构、驱动开发顺序、验收标准及团队交接设计到可执行层级。**本轮不启动工程环境安装/校验、Keil Target Build、驱动编码、烧录、上板、功率输出。**

## 0. 执行边界和版本关系

1. **当前仅做实施前设计和资料准备**。SW-00 环境核对、SW-01 正式 Keil/官方 SDK 目标工程创建，均为未来实施任务，当前不执行。
2. 负责人反馈云途 EVB 已初步尝试 **Keil + ST-Link**，这是已知事实；工具版本、连接、Flash 成功与 Target 构建结果均未提供客观证据，不标记 PASS，也不强制改用其他 IDE。
3. 目前正式 PCB 尚未完成，但 MCU 驱动和算法可以在未来使用开发板开展无功率验证。开发板严禁直接接真实拖挂制动功率链；未来涉及功率实验须独立危险分析、硬件审查和台架准入。
4. **V1** 目标是真实模块与同步制动功能测试；**V2** 是完整 LCD 首次交付产品；**V3** 才开发手机 App 交付产品。三版共用业务核心，不做三套制动算法。
5. 已存在的旧 firmware/app 源码不作为新工程实现依据；此前交付的 V0.1/V0.2 Host 模板可作为候选参考，不能未经审查直接成为目标固件基线。
6. **标准底线不降低**：统一严格参考已批准的汽车电子软件工程质量规范；代码审查、静态规则、需求追踪、异常路径与测试证据要求必须纳入未来每个工作包；不宣称已经通过 MISRA/ASPICE/ISO 26262 合规评定。

## 1. 整体软件体系：职责先于文件名

```text
                     产品配置 / 维护 / 状态
                   ┌────────┴─────────┐
                   │ V2 LCD │ V3 BLE/App │  ← 仅配置和观测，不属于制动实时闭环
                   └────────┬─────────┘
                            ↓ 统一配置/状态合同
                ┌──────────────────────────────┐
  Brake Intent →│ 输入资格/质量 ────┐           │
                │                 ↓            │
 Motion / IMU → │ 运动质量/时间 ─→制动控制决策│ ASW
                │                 ↓            │
                │   参数/状态/故障/运行资格      │
                └───────────────┬──────────────┘
                                ↓ 逻辑制动请求（非功率许可）
                  独立执行许可/受控反馈合同
                                ↓
                 BSW Services / Device / Driver
                                ↓
        BoardCfg + 云途 SDK + MCU + 以后真实产品功率硬件

  物理功率使能/默认态/失效关断：另由硬件与系统安全设计证明
```

业务与平台分层依赖约束：

| 层 | 负责 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| ASW | 制动意图质量、运动质量、业务状态、参数、诊断、控制请求 | 经评审的基础接口/数据快照 | MCU 寄存器、官方 SDK 类型、GPIO/中断处理器、BLE AT 指令 |
| BSW Services | 单调时间、受控存储、诊断日志、事件/信号发布 | BSW 驱动、BoardCfg 抽象 | 上层重量档控制律及 LCD 页面 |
| BSW Devices | 具体加速度模块、蓝牙模块、LCD 等设备协议和状态 | UART/CAN/I²C/SPI 等基础驱动 | 上层制动决策、直接开放功率输出 |
| BSW Drivers | MCU 外设的可控生命周期、错误、IRQ/DMA | 官方 SDK、BoardCfg、Service 允许的底层函数 | 设备协议、业务重量档 |
| BoardCfg/Platform | MCU/开发板 Rev、时钟树、PinMux、外设实例、启动/链接与供应商工具 | MCU/板卡版本、官方 SDK | 产品业务配置、业务状态机 |
| APP Integration | 初始化编排、调度入口、依赖注入和测试模式的装配 | 受控对外模块接口 | 大量协议解析、ISR/DMA 状态管理塞入 `main.c` |

不人为追求 AUTOSAR 全量框架；但每个实际边界均保持充分的职责定义、版本控制、检查工具和审查证据，不得以“精简”为理由省略质量步骤。是否引入 RTOS 取决于时序、故障独立性与资源实测的正式决策，不预先锁定裸机/RTOS。

## 3. 五种必须稳定的数据/事件契约

这里定义数据的**语义**而不是固定 C ABI，避免在缺少硬件与安全分析时提前冻结结构体布局。

| 契约ID | 数据与生产/消费方向 | 必须携带或能证明 | 失效处理的系统要求 |
|---|---|---|---|
| SW-ICD-01 | 制动意图：采样→ASW | 原始来源/值、可信标志、单调时间戳、更新周期依据 | 无信号、接线异常、时效过期不可被当作有效 `false` |
| SW-ICD-02 | 运动信号：设备层→ASW | 单位、方向/坐标轴、量程、标定来源、时间戳、质量 | 无效、饱和、通信超时、安装方向异常均应可区分 |
| SW-ICD-03 | 控制：输入/配置/资格→逻辑请求 | 采样版本、参数版本、受限原因、请求值、有效期 | 旧输入/错配参数拒收；具体控制律与功率动作 OPEN |
| SW-ICD-04 | 执行：逻辑请求→权限边界→执行反馈 | 请求编号、许可状态、观测反馈与硬件故障状态 | 请求/许可/实际电流/实际制动效果不许混用 |
| SW-ICD-05 | HMI参数与状态：设备权威→LCD/后续App | 设备身份、配置事务阶段、当前生效与已保存版本、状态新鲜度 | 断链或过期不能显示设备正常或设置完全成功 |

**配置事务注意**：`RECEIVED`/`VALIDATED`/`ACCEPTED`/`EFFECTIVE`/`PERSISTED`/`READBACK_CONFIRMED` 是结果证据，不承诺任何参数均按此固定顺序线性运行。各参数是否允许行驶中改变及生效/保存原子性，在安全分析后定义。

## 4. 运行时、并发与内存的预设计决策

| 对象 | 现阶段需明确的工程原则 | 正式冻结依据 |
|---|---|---|
| 执行模型 | 主循环/周期任务/事件/RTOS 均作为候选；不得凭便利性预选 | 任务 WCET、故障隔离、RAM、IRQ负荷、诊断要求和实测 |
| ISR | 最短路径收集事件/状态；禁止在 ISR 内执行长协议解析、耗时 NVM 写或应用控制逻辑 | 芯片/SDK IRQ 机制与时序分析 |
| DMA | 缓冲所有权和 CPU/DMA 可见性必须明示；缓存一致性、原子性、溢出和重入需验证 | MCU DMA/Cache/SDK 实际行为 |
| 参数存储 | 原子提交/版本/校验和上电恢复、写入次数预算、有效配置回退策略 | NVM硬件与安全约束 |
| 时间 | 采用受控单调计时、时间戳和新鲜度；不让 UART/CAN ISR 直接决定系统时基 | SDK/芯片计数行为与 WCET |
| 静态资源 | 设计线程/任务栈、ISR 栈、队列、缓冲上限，禁止在异常路径无限增长 | RAM/Flash布局、压测及栈分析 |
| 看门狗 | 独立考虑喂狗前提、触发后的系统资格与硬件故障响应；严禁无条件喂狗掩盖锁死 | 安全分析、MCU WDG及硬件保护 |
| 失效输出 | 只定义“故障会影响资格/许可且必须可诊断”；不能统一假定失效时物理制动输出清零最安全 | 真实车辆危险分析与功率级拓扑 |

## 7. 真正进入代码开发时的执行顺序（**仅是未来准入路线**）

```text
[本轮 PRE 软件架构/资料/测试设计]
        ↓ 后续明确开工授权

        ↓

        ↓

        ↓

        ↓
SW-06   T0/T1/T2无功率验证与故障注入
        ↓ 另外的安全/硬件/台架独立许可
SW-07   实际功率/制动执行测试（当前 BLOCKED）
        ↓
V2 LCD 完整用户功能与产品验收 → V3 App/蓝牙完整交互
```

**不要把这一流程写成正在执行或全部通过。** 不同任务之间可并行开发纯 Host 算法，但不可绕开真实 Target 前置条件声称外设驱动可用。
