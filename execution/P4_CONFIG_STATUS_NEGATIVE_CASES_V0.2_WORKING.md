## 1. 需要共享的设备权威事实

| 系统事实 | 设备/用户可识别的意义 | 需要的错误或不确定状态 | 来源 |
|---|---|---|---|
| 当前配置 | 生效参数及对应版本 | 未就绪、非法、版本不符 | DD-06, SYS-CFG |
| 已保存配置 | 非易失存储确认的参数版本 | 写入失败、保存结果未知 | DD-06, SYS-CFG |
| 设备运行状态 | 设备内部判定的运行资格与当前业务阶段 | 初始化/未就绪/故障/受限 | DD-04, SF-01/07 |
| 状态观察有效性 | 用户能否信任最新设备状态 | 通信断开、过期、设备身份不明 | DD-04, HA-11 |
| 参数修改请求 | 请求来源、身份和期望目标 | 重放、重复、错误版本、超时、权限拒绝 | DD-06, HA-10 |
| 故障与恢复 | 故障仍有效、已恢复、需维修/重新确认 | 不能仅因 UI 清除告警就视为恢复 | DD-04, SSR-13 |

## 2. 设计需要覆盖的负向用例

| 用例编号 | 事件 | 必须可观察的结果 | 尚待产品决定 |
|---|---|---|---|
| TC-CFG-01 | 参数越界 | 明确拒绝，不改变设备已生效值 | 档位/等级正式范围 |
| TC-CFG-02 | 设备连接后重复提交相同请求 | 可识别重复/查询结果，不让用户误以为多次独立改变 | 请求幂等性合同 |
| TC-CFG-03 | 命令已受理，但通信中断 | 用户显示“结果未确认”并通过重连查询权威版本 | 重试/超时策略 |
| TC-CFG-04 | 当前工况禁止修改关键参数 | 明确拒绝并保持受控版本，不产生隐式生效 | 运行中允许修改哪类参数 |
| TC-CFG-05 | 配置生效后持久化失败 | 生效和保存状态分别报告，不把保存失败掩盖为完全成功 | 各参数是否允许先应用后保存 |
| TC-CFG-06 | 写入中突然断电/复位 | 重启时能识别有效版本与异常，不使用损坏参数 | NVM 及断电保持要求 |
| TC-CFG-07 | 返回值与设备读回不一致 | 明确不一致，不用本地 UI 缓存覆盖设备状态 | 版本/校验字段方案 |
| TC-STA-01 | 状态通信超时、设备暂不可达 | 显示设备状态“未知或过期”，不显示正常 | 刷新时限 |
| TC-STA-02 | 输入失效/传感数据过期 | 设备能区分有效与不可用；故障后续动作待分析 | 失效阈值和动作 |
| TC-STA-03 | 设备报告受限或故障 | 交互界面展示限制/故障及其来源 | 故障等级与恢复条件 |
| TC-STA-04 | 无线断开但主控仍运行 | 无线失联本身不替代主控制器安全判断 | 各产品 Variant 连接依赖 |
| TC-STA-05 | 状态新旧版本不一致或乱序 | 不以旧消息覆盖新鲜、已确认状态 | 版本/排序机制 |

这些是**系统可观测验收场景**，不是已编写或通过的测试。所有状态均为 `TEST_PLAN / NOT_RUN`。
