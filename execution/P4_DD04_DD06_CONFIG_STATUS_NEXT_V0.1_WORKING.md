## A. 立即可深化：DD-06 用户配置事务语义

**目的**：用户调节重量制动档/制动力时，系统必须明确区分命令处理阶段，避免 UI 把“发送成功”当作制动行为已改变。

| 事务阶段 | 可观测含义 | 不能推断 |
|---|---|---|
| RECEIVED | 设备收到完整可识别请求 | 参数已合法或生效 |
| VALIDATED | 参数范围、版本、权限、适用 Variant 等形式校验已做 | 当前工况允许生效 |
| ACCEPTED | 通过当前规则判定，允许进入受控应用事务 | 已生效或已写入非易失存储 |
| EFFECTIVE | 设备实际采用新配置，并报告生效版本 | 已可靠保存到掉电仍保持 |
| PERSISTED | 已确认所需持久化过程成功 | 手机已经读取并确认状态 |
| READBACK_CONFIRMED | 读回与设备有效版本一致 | 制动力物理映射与车辆标定已通过 |

**系统级要求候选：**

1. 每次参数变更要有请求身份、来源、期望变更和设备上报的状态/原因；具体协议编码、时序与字段长度待实现设计。
2. 用户应区分当前显示的**待编辑值**、设备**实际生效值**、设备**已保存值**；未完成提交或断链后不能把缓存当作设备现值。
3. 值非法、版本不兼容、无权限、当前运行条件不许可、存储失败、读回不符等均应给出可区分结果；未决的行驶中调参许可不在此擅自确定。
4. 请求重复/超时/断线/重连不应导致用户误以为同一设置已成功执行；请求身份和结果查询/回读机制须在后续 ICD 设计中定义。
5. 生效与持久化的**实际先后策略**取决于产品许可与风险分析；本表表达证据粒度，不武断规定所有参数在所有工况下必须立即应用。

**拟验证场景（均为计划，NOT_RUN）**：非法值拒绝、重复请求、旧版本请求、断链但设备已受理、运行状态禁止改变、NVM 写失败/掉电中断、设备重启后恢复、读回版本不一致、App 状态缓存过期。

## B. 立即可深化：DD-04 状态与交互语义

- `INIT` / `INHIBITED` / `READY` / `ACTIVE` / `DEGRADED` / `FAULT` / `SERVICE` 是目前获批的**系统状态类别**，不等于未来的 C 枚举或硬件输出许可。
- 故障报告应最少区分**设备自身诊断状态**与**通信是否可信/最新**：无线失联是“未知/未更新”，不能显示“设备正常”。
- 不对各类故障事先指定物理制动输出动作，特别是不能统一规定“故障立即清零”。
- 配置事务可能被工况限制；与 HA-10（无线/配置异常）和 HA-11（误导状态）追溯。
- 状态转换、诊断等级、恢复条件仍需目标车型、轮端执行器及风险分析确定的受控证据。

## C. 集中产品取舍 C-01～C-06 —— 一次准备、一次呈报

| 组 | 需要最终确定的产品事项 | 当前缺少的可信依据 | 允许先行设计的部分 |
|---|---|---|---|
| C-01 | 首发市场/车辆类别/质量/轴数、安装方式 | 市场定位、目标车型及适用法规研究 | 产品适用/排除表的字段与验证规则 |
| C-02 | 电磁制动器类型/轮端规格、供电/线束及应急制动边界 | 制动器供应商原始规格、供电/安装拓扑 | 功率执行需求、故障类别和证据清单 |
| C-03 | 制动意图来源、运动信息用途和主辅关系 | 实际车辆接口及传感器模块依据 | 输入身份、质量、时间/单位合同 |
| C-04 | 首发 LCD/App Variant、Android/iOS 支持 | 产品商业策略和使用场景 | HMI 共用业务状态及设备端权威状态语义 |
| C-05 | 重量档/制动力调节级别与默认/保存规则 | 产品覆盖、用户体验与标定策略 | 参数事务合法性和证据粒度；1–10 仍候选 |
| C-06 | 手动制动、Boost、倒车、OTA、侧摆辅助的版本归属 | 风险分析、商业优先级、成本/资源 | 增强功能条件性边界，不默认进入首版 |

**取舍顺序建议**：先解决 C-01/C-02/C-03 的实体产品事实与安全边界，同时并行筹备 C-04/C-05/C-06。它们是同一轮**产品定义决策包**，不再拆成多个 P 阶段审批。
